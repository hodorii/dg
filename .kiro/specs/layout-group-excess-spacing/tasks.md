# 구현 계획 - layout-group-excess-spacing

## 정의
버그픽스 순서(재현 테스트, 불변 테스트, 수정, 양쪽 통과)로 설계의 수정을 구현하는 계획이다. 같은 파일을 고치는 `bpmn-pool-message-layout`이 main에 합쳐지고 그 테스트가 모두 통과한 뒤 시작한다. 작업마다 검토에서 0.4.0 대비 CPU 시간과 최대 RSS를 함께 본다.

- [ ] 1. 재현 테스트 (수정 전 실패)
- [ ] 1.1 축소 입력과 재현 문서 블록의 재현 테스트
  - _DoneWhen: 빈 층 접기(6노드), 그룹 줄(6노드), 계단(10노드), 라벨 폭(4노드), 1.5 최소 문서 넷(BT 끝 노드, TB 시작 노드, TB 곁가지 사슬, RL 끝 노드)과 `test-plan.md` "시험 아키텍처" 블록 두 판(10-02, 10-06)을 렌더링해 곧은 행 연속 2행 이하, 그룹 안 곧은 행 연속 2행 이하, 꺾임 사이 곧은 행 없음, 라벨 행 말고는 빈 열 띠 없음, 라벨 글자 모두 보임, 이름을 정한 곁가지 노드가 닿는 노드 바로 옆 층에 있음을 단언하는 테스트가 수정 전 코드에서 각자의 결함으로 실패하는 것을 출력으로 확인_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 2.1, 2.2, 2.3, 2.4, 2.5_
  - _Difficulty: mid_
  - _Boundary: 흐름도 렌더링 테스트_

- [ ] 2. 불변 테스트 (수정 전 통과)
- [ ] 2.1 (P) 그룹 없는 흐름도의 결과 고정 속성 테스트
  - _DoneWhen: 무작위 그룹 없는 흐름도(노드 2~10, 라벨 있는 간선 포함, TB, BT, LR, RL)를 깃발 끈 배치의 최종 층으로 걸러 곁가지가 이미 바로 옆 층인 문서만 남기고, 그 렌더링 해시를 수정 전 코드로 기록해 같음을 단언하는 테스트가 수정 전에 통과, 걸러진 표본 수 최솟값 단언, 실패 시 시드와 문서 출력_
  - _Requirements: 3.1_
  - _Difficulty: mid_
  - _Boundary: 흐름도 렌더링 테스트_
- [ ] 2.2 (P) 그룹 있는 흐름도의 관계 보존 속성 테스트
  - _DoneWhen: 무작위 그룹 있는 흐름도(그룹 1~3, 중첩 포함, 노드 3~12, 라벨 있는 간선 포함, 네 방향)에서 렌더링 결과의 노드, 간선 연결과 방향, 화살표, 라벨 글자, 그룹 중첩과 제목이 입력과 같은 관계이고 선이 노드나 라벨을 지나지 않음을 단언하는 테스트가 수정 전에 통과, 실패 시 시드와 문서 출력_
  - _Requirements: 3.2_
  - _Difficulty: high_
  - _Boundary: 흐름도 렌더링 테스트_
- [ ] 2.3 (P) 흐름도가 아닌 예제의 결과 고정 테스트
  - _DoneWhen: `examples/*.md`의 흐름도가 아닌 블록 렌더링 해시(기본, TB, LR × 폭 80, 120, 200)를 수정 전 코드로 기록하고 같음을 단언하는 테스트가 수정 전에 통과_
  - _Requirements: 3.3_
  - _Difficulty: low_
  - _Boundary: 흐름도 렌더링 테스트_

- [ ] 2.4 (P) 그림 크기 기록 테스트
  - _DoneWhen: 재현 문서 블록 셋(10-02, 10-06, 단계와 회차)과 `examples/*.md` 흐름도의 폭 80~240(20 간격), 네 방향 렌더링 행과 열을 수정 전 코드로 기록하고, 행이 max(2행, 5%)보다 늘면서 면적도 줄지 않는 경우가 없음(수정 전 원문이면 그림 허용)을 단언하는 테스트, 그리고 시드 고정 무작위 흐름도 묶음(3.5의 생성기 조건, 그룹 없음과 그룹 있음 각 1000건 이상)의 수정 전 행과 열을 기록하고 곁가지가 있는 (문서 × 폭)을 분모로 넘는 비율이 그룹 없음 3%, 그룹 있음 8% 이하이며 원문으로 떨어진 경우 0을 단언하는 테스트가 수정 전에 통과_
  - _Requirements: 3.5_
  - _Difficulty: mid_
  - _Boundary: 흐름도 렌더링 테스트_
