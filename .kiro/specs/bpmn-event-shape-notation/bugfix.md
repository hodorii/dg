# Bugfix — bpmn-event-shape-notation

## 정의
BPMN 그림에서 이벤트와 활동(태스크·서브프로세스)을 한눈에 가르려는 사용자를 위해, 이벤트 노드가
태스크와 같은 둥근 상자 실루엣으로 그려지는 결함을 고쳐 BPMN 이벤트 표기(원)로 그리게 하는 수정이다.
사용자 지적(2026-09-27): "이벤트는 rect 빼고 이벤트 notation을 표시한다", "이벤트는 원으로 표시하고,
activity/task/subprocess는 round rect가 기본인데".

## 재현 절차
1. 환경: 커밋 `956b885`(bpmn-xml 구현) 기준, `cargo test` 427개 통과 상태. 도형 단위 테스트
   `layout::shape::tests::draw_rows()`(손으로 만든 sections, `Theme::none()`)와
   `cargo run -- -P --width 100 examples/bpmn.md`.
2. 입력(도형): `Shape::Event(Start/Intermediate/End)` 본문 `["Go"]`; 대조로 `Shape::Round`·`Shape::Stadium`
   같은 본문.
3. 관찰(도형 — 테스트 `event_start_intermediate_end_render_with_position_glyphs`의 리터럴):
   - Event(Start) → `["╭──────╮", "│ ○ Go │", "╰──────╯"]`
   - Event(Intermediate) → `["╭──────╮", "│ ◎ Go │", "╰──────╯"]`
   - Event(End) → `["┏━━━━━━┓", "┃ ● Go ┃", "┗━━━━━━┛"]`
   - Round → `["╭────╮", "│ Go │", "╰────╯"]`, Stadium → `["╭──────╮", "│  Go  │", "╰──────╯"]`
     (`measure`·`draw` 규칙에서 유도, 실행 리터럴 `cylinder_has_lid`와 같은 기하 — 실행으로 확인하지 않음)

   세 이벤트와 Round·Stadium이 모두 "위·아래 가로선 + 양옆 세로선 + 모서리 글자 네 개"인 세 줄 상자다.
   Event(Start)와 Stadium은 테두리 12칸이 글자 단위로 같고 안쪽 `○` 한 칸만 다르다. 종료 이벤트는 굵은
   각진 상자 — 원이 아니라 또 다른 상자.
4. 관찰(실물): `examples/bpmn.md` 첫 프로세스 렌더링.
   ```
                     ╭───────────╮
   ╭─────────────╮   │ 주문 검토 │   ┏━━━━━━━━┓
   │ ○ 주문 접수 │──▶│  «user»   │──▶┃ ● 완료 ┃
   ╰─────────────╯   ╰───────────╯   ┗━━━━━━━━┛
   ```
   시작 이벤트(왼쪽)와 태스크(가운데)가 같은 둥근 상자다. 둘째 협업 그림에서도 `│ ○ «message» │`·
   `│ ◎ 시한 초과 │`·`┃ ● 주문 취소 ┃`가 모두 상자로 그려진다.
5. 관찰(접점): 위 그림에서 `▶`는 종료 이벤트의 `┃` 테두리 왼쪽에 닿고 `●`는 그 두 칸 안쪽이다 —
   흐름이 원에 닿지 않고 상자에 닿는다.

## Boundary Context
- **In scope**: `Shape::Event` 세 위치(Start·Intermediate·End)의 측정·그리기; 그 출력에 의존하는 기존
  테스트 기대값 갱신(`layout::shape`·`layout::graph`·`bpmn::mod`); 이벤트 노드에 드나드는 간선의 접점
  확인; `Shape::Event` 어휘 주석
- **Out of scope**: 활동 모양 — `Shape::Round`(태스크·호출 활동)·`Shape::Subprocess`는 둥근 상자 그대로
  (사용자 확정 2026-09-25, 2026-09-27 재확인 — 이벤트가 달라 보여야 할 기준점); `Shape::Circle`의 같은
  "둥근 상자" 문제(mermaid `(( ))`·PlantUML `circle` 어휘 — 별도 스펙 후보); `Rect`·`Stadium`·`Diamond`
  등 다른 모양; 배치기(`layout::graph`) 접점 규칙 변경; `bpmn::model`·`validate`·`lower`·`parse_xml`의
  의미 논리(도형 매핑 `ElementKind::Event → Shape::Event(position)` 그대로); 새 BPMN 개념·트리거 아이콘
  글자·중간 이벤트 이중선; 예제 파일 추가

## Behaviors

### 1. 현재 동작 (결함)
- 1.1: [시작 이벤트 노드 + 이름 한 줄] → [`Round`·`Stadium`과 같은 세 줄 둥근 상자 실루엣으로 그려지고,
  안쪽 `○` 한 칸만 다르다]
- 1.2: [중간 이벤트 노드] → [1.1과 같은 상자, 안쪽 글자만 `◎`]
- 1.3: [종료 이벤트 노드] → [굵은 각진 상자 `┏━┓`·`┃`·`┗━┛` — 원이 아니라 상자]
- 1.4: [이름 없는 이벤트 노드] → [`["╭────╮", "│ ○  │", "╰────╯"]` — 글자 하나를 위한 3×6 상자]
- 1.5: [이벤트 이름 아래 둘째 줄 `«timer»`] → [네 줄 상자 안에 이름·둘째 줄]
- 1.6: [이벤트 노드에 간선이 닿음(왼쪽→오른쪽)] → [`▶`가 상자 테두리(`│`/`┃`) 왼쪽에 닿고 위치 글자는 두
  칸 안쪽 — 흐름이 원에 닿지 않는다]

### 2. 기대 동작
- 2.1: [시작 이벤트 노드 + 이름 "Go"] → [`["○ Go"]` — 테두리 글자(`╭╮╰╯─│┏┓┗┛━┃`) 없이 원 글자와
  이름만 한 줄; `Round`의 `["╭────╮", "│ Go │", "╰────╯"]`와 실루엣이 다르다]
- 2.2: [중간 이벤트 노드] → [`["◎ Go"]` — 이중 원 글자]
- 2.3: [종료 이벤트 노드] → [`["● Go"]` — 굵은 선 없이 채운 원 글자가 종료를 나타낸다]
- 2.4: [이름 없는 이벤트 노드] → [`["○"]` 1×1, 패닉 없음]
- 2.5: [본문 `["Go", "«timer»"]`] → [`["○ Go", "  «timer»"]` — 둘째 줄이 이름 시작 열에 맞춰 아래 줄에
  오고, 이름은 굵게, 둘째 줄은 흐리고 기울여, 위치 글자는 강조색]
- 2.6: [이벤트 노드에 간선이 드나듦] → [위→아래: `▼`가 이벤트 줄 바로 위 줄, 이벤트가 차지한 열 범위 안;
  왼쪽→오른쪽(본문 두 줄 이하): `▶`가 위치 글자 바로 왼쪽 칸]

### 3. 불변 동작 (회귀 방지)
- 3.1: [`Rect`·`Round`·`Stadium`·`Cylinder`·`Diamond`·`Hexagon`·`Subroutine`·`Circle`·`Note`·`Plain`·`Actor`·
  `Interface`·`Subprocess`·상태도 `Start`/`End`] → [출력이 글자·스타일 단위로 이전과 같다(기존 도형·배치
  테스트 무수정 통과)]
- 3.2: [태스크 `Round` + 둘째 줄 `«user»`, 서브프로세스 `[+]`] → [그대로(bpmn-shapes 2.1~2.3, 3.2~3.4)]
- 3.3: [`lower()`의 이벤트 요소] → [`Shape::Event(position)`, 본문 `[이름]`/`[이름, "«trigger»"]`/`[]`
  그대로(bpmn-model 계약)]
- 3.4: [이벤트에 쓰는 글자] → [`○`·`◎`·`●` 외 새 글자 없음 — 기본 CJK 모노 폰트 커버리지 허용 목록 테스트
  그대로(bpmn-shapes 5.2)]
- 3.5: [default 흐름 빗금·서브프로세스 `[+]` 보존·레인 배치·이름 없는 이벤트 등 조합] → [기존 배치
  테스트 그대로 통과, 패닉 없음]
- 3.6: [`examples/*.md` 중 `bpmn.md` 외 전부] → [`dg -P --width 100` 출력 바이트 동일]
- 3.7: [주문 처리 협업(`bpmn::tests`의 손 모델·bpmn.io fixture)와 손 그래프(`layout::graph::tests`)] →
  [폭 100 안에서 렌더링되고 `○`·`●`·`◎`·`«user»`·`«service»`·`«message»`·`«error»`·`× 재고 있음?`·`╱`·`╌`가
  모두 있다 — 굵은 세로선 `┃`만 기대 목록에서 빠진다(종료 이벤트가 더 이상 만들지 않으므로)]
