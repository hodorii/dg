# Bugfix — diagram-lr-tail-label-position

## 정의
가로(LR) 방향 그래프형 다이어그램을 읽는 사용자를 위해, 관계의 from측(카디널리티·다중성·관계
이름) 라벨이 항상 자신이 속한 개체 상자 바로 옆에 표시되도록 고치는 결함 수정이다.

## 재현 절차
1. 환경: `cargo build --release`로 빌드한 `dg`, 비대화형 출력(`-P -s none`), 폭 140
   (`-w 140`, 줄바꿈으로 인한 재시도를 배제하기 위함).
2. 입력: 같은 레이어(같은 세로 열)에 상자 폭이 서로 다른 개체 두 쌍을 넣은 ER 소스.
   ```
   erDiagram
       A ||--o{ B : rel1
       LONG_ENTITY_NAME_HERE ||--o{ C : rel2
   ```
   명령: `dg -P -s none -d -l mermaid --direction lr --er-notation text -w 140 <파일>`
3. 관찰 결과:
   ```
   ┌───┐                     1     0..N ┌───┐
   │ A │─────────────────────rel1───────│ B │
   └───┘                                └───┘

   ┌───────────────────────┐ 1     0..N ┌───┐
   │ LONG_ENTITY_NAME_HERE │─rel2───────│ C │
   └───────────────────────┘            └───┘
   ```
   `LONG_ENTITY_NAME_HERE → C` 쪽은 `1`과 `rel2`가 `LONG_ENTITY_NAME_HERE` 상자 바로 옆에
   붙어 있지만, `A → B` 쪽은 `1`과 `rel1`이 `A` 상자에서 멀리 떨어져 선 중간 지점 근처에
   표시된다. 같은 소스를 `--direction tb`로 렌더링하면 두 관계 모두 각자의 상자 바로 아래에
   정확히 표시된다. 같은 조건을 `classDiagram`의 다중성 라벨(`"1" --> "many"`)로 재현해도
   동일하게 어긋난다.

## Boundary Context
- **In scope**: LeftRight(가로) 방향 그래프형 다이어그램(ER, 클래스 등, 공통 그래프
  배치기를 쓰는 다이어그램)에서 관계의 from측에 붙는 텍스트 라벨(카디널리티, 다중성,
  관계 이름)의 가로 위치
- **Out of scope**: to측(head) 라벨 위치(정상 동작), TB(세로) 방향(정상 동작), 까치발(크로우풋)
  기호 자체의 방향·모양(`diagram-crow-foot-orientation`에서 이미 고정됨), 그래프 배치기를 쓰지
  않는 다이어그램(시퀀스 등)

## Behaviors

### 1. 현재 동작 (결함)
- 1.1: [LR 방향에서 같은 레이어에 상자 폭이 다른 개체가 함께 있고, 폭이 더 좁은 개체에서
  관계가 시작할 때] → [`--er-notation text`/`both`의 from측 카디널리티 텍스트가 그 개체
  상자에서 떨어져 선 중간 지점 근처에 표시된다]
- 1.2: [같은 조건에서] → [관계 이름 라벨(예: `rel1`)도 from측 개체 상자가 아니라 같은
  레이어의 더 넓은 개체 상자 기준 위치에 표시된다(기본 까치발 표기에서도 재현됨)]
- 1.3: [같은 조건을 classDiagram의 다중성 라벨로 재현할 때] → [from측 다중성 라벨도 같은
  방식으로 상자에서 떨어져 표시된다(ER 전용 결함이 아니다)]

### 2. 기대 동작
- 2.1: [LR 방향에서 같은 레이어에 상자 폭이 다른 개체가 함께 있어도] → [from측 카디널리티
  텍스트는 항상 자신이 속한 개체 상자 바로 옆에 표시된다]
- 2.2: [같은 조건에서] → [관계 이름 라벨도 항상 from측 개체 상자 바로 옆에서 시작한다]
- 2.3: [classDiagram 등 같은 그래프 배치기를 쓰는 다른 다이어그램에서도] → [from측 다중성
  라벨이 자신이 속한 개체 상자 바로 옆에 표시된다]

### 3. 불변 동작 (회귀 방지)
- 3.1: [TB(세로) 방향으로 렌더링] → [카디널리티·관계 라벨·다중성 표기가 지금처럼 각 개체
  바로 아래에 정확히 표시된다]
- 3.2: [LR 방향에서 to측(head) 카디널리티·다중성·관계 라벨] → [지금처럼 도착 개체 상자
  바로 옆에 정확히 표시된다]
- 3.3: [까치발(크로우풋) 기호 자체] → [모양과 상자에 붙는 위치가 지금처럼 유지된다]
