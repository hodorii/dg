# Bugfix — gitgraph-dot-id-gap

## 정의
gitGraph를 읽는 사용자를 위해, 커밋·병합 점 글자와 그 뒤 id 글자 사이에 최소 한 칸 공백을 두어
점 글자가 다음 글자를 가리지 않게 하는 결함 수정이다.

## 재현 절차
1. `gitGraph\n  commit id: "root-long-id"\n`을 `dg -P -s none -d -l mermaid`로 렌더링한다.
2. 출력 둘째 줄이 `main  ●root-long-id`로 나온다. 바이트 단위로 확인하면(`od -c`) `●`(UTF-8
   `342 227 217`) 바로 다음 바이트가 공백 없이 곧장 `r`이다 — 점 글자와 id 글자 사이 공백이
   전혀 없다.
3. 실제 터미널(사용자 스크린샷, `스크린샷 2026-09-22 13-31-52.png`)에서는 이 간격 없음 때문에
   `●` 글자의 시각적 폭이 폰트에 따라 정확히 1칸을 넘어 보여, id의 첫 글자("r")가 가려져
   `●oot-long-id`처럼 보인다. dg가 만든 텍스트 자체(위 2번)는 글자 손실이 없다 — 간격 없음으로
   인한 시각적 겹침이지 텍스트 생성 결함이 아니다.
4. 같은 현상이 세로 모드(`gitGraph TB:`)와 병합 점(`◉`, id는 없지만 다음 요소와 인접)에도 동일한
   원인(점 뒤 공백 없음)으로 재현 가능하다.

## Boundary Context
- **In scope**: 가로 모드(`build`)·세로 모드(`build_vertical`) 모두에서 커밋 점과 그 뒤 id 글자
  사이 최소 한 칸 공백, 이에 따른 폭 계산(`slot`/`col`/`total`) 조정
- **Out of scope**: 직전 스펙(`gitgraph-junction-polish`)에서 고친 "id 글자 뒤 → 분기 연결선"
  간격(이미 해결, 그대로 유지), 점 글자 자체의 폭 계산 변경(`unicode-width` 기준 1칸 유지 — 실제
  터미널 렌더링 폭 차이는 이번에 추가하는 여백으로 흡수), 다른 다이어그램형의 점·아이콘 간격

## Behaviors

### 1. 현재 동작 (결함)
- 1.1: [가로 모드, 커밋에 id가 있음] → 점 글자 바로 다음 칸부터 id 글자가 시작됨(공백 없음)
- 1.2: [세로 모드, 커밋에 id가 있음] → 점 글자 바로 다음 칸부터 id 글자가 시작됨(공백 없음)

### 2. 기대 동작
- 2.1: [가로 모드, 커밋에 id가 있음] → 점 글자와 id 글자 사이에 최소 한 칸 공백이 있음
- 2.2: [세로 모드, 커밋에 id가 있음] → 점 글자와 id 글자 사이에 최소 한 칸 공백이 있음

### 3. 불변 동작 (회귀 방지)
- 3.1: [id가 없는 커밋(`commit`만)] → 점 글자만 찍히고 레이아웃 폭에 불필요한 여백이 추가되지
  않음(기존과 동일)
- 3.2: [`gitgraph-junction-polish`에서 고친 세로 모드 "id 글자 뒤 → 분기 연결선" 간격] → 계속
  유지됨
- 3.3: [`gitgraph-branch-distinction`의 트랙별 색·선패턴, `gitgraph-junction-polish`의 둥근
  모서리] → 계속 유지됨
- 3.4: [항상] → 패닉 없음, 기존 `gitgraph.rs` 테스트 전량 통과
