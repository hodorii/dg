# Bugfix — layout-crossgroup-edge-blowup

## 정의
"최소 자원·빠른 응답"이 핵심 가치인 dg에서, subgraph 사이를 가로지르는 간선이 여럿인
flowchart 코드펜스를 담은 실사용 문서를 열 때 렌더링이 수 초에서 수십 초 이상 걸리는
(그러면서 결과는 대개 코드블록 폴백인) 결함을, 그려지는 결과를 한 바이트도 바꾸지 않고
고치는 수정이다.

## 재현 절차
1. 환경: `cargo build --release`(rustc 1.96.0) 바이너리, 비대화형 `-P --width 120`,
   `/usr/bin/time -f "%e sec %M KB"`. 문서는 이 저장소 밖 파일이라 경로만 인용한다:
   `../agentic-psdd/docs/design.md`(33KB, 485줄, mermaid 펜스 5개).
2. 관찰(실사용 문서): 문서 전체 2.92초(같은 세션 뒤쪽 재측정 1.72초 — 부하에 따라 흔들림).
   펜스를 하나씩 떼어 재면 2번째 펜스(`flowchart LR`, subgraph 8개, 노드 52개, 간선 48개)만
   2.58초, 나머지 4개(`flowchart TB` 13간선, `sequenceDiagram` 2개, `stateDiagram-v2`)는
   0.00~0.12초. 2번째 펜스는 결국 폭 120에 들어가지 못해 원문 코드블록으로 폴백된다 —
   2.58초는 그 폴백을 결정하는 데 쓰인 시간이다.
3. 관찰(메모리): 최대 상주는 빌드 환경에 따라 4~5MB(설치 바이너리) 또는 7.5~7.8MB(이
   세션에서 `cargo build`한 바이너리)로, 같은 빌드 안에서는 그래프 크기·수정 전후와 무관하다.
4. 합성 입력(변인 통제): subgraph 8개(그룹당 6~7노드 사슬)에 두 그룹 사이 무작위 간선 N개를
   더한 `flowchart LR`. 기본형 외에 허브형(교차 간선이 모두 그룹 0을 거침), 사슬형(그룹
   0→1→…→7을 잇는 간선 7개를 먼저 둠), 불균등 라벨형(노드 30%에 20~40자 라벨)을 둔다.
   ```python
   import random, sys
   variant, n, seed, out = sys.argv[1], int(sys.argv[2]), int(sys.argv[3]), sys.argv[4]
   rnd = random.Random(seed); random.seed(seed); lines = []; groups = {}
   for g in range(8):
       size = 6 if g < 4 else 7
       groups[g] = [f"S{g}_{j}" for j in range(size)]
       def lab(k):
           if variant == "labels" and rnd.random() < 0.3:
               return f"s{g}_{k} " + "very long label text " * rnd.randint(1, 2)
           return f"s{g}_{k}"
       lines.append(f"  subgraph G{g}")
       lines += [f"    S{g}_{j}[{lab(j).strip()}] --> S{g}_{j+1}[{lab(j+1).strip()}]" for j in range(size - 1)]
       lines.append("  end")
   if variant == "chain":
       lines += [f"  {groups[g][-1]} --> {groups[g+1][0]}" for g in range(7)]
   for _ in range(n):
       if variant == "hub":
           g2 = random.randrange(1, 8); a, b = random.choice(groups[0]), random.choice(groups[g2])
           if random.random() < 0.5: a, b = b, a
       else:
           g1, g2 = random.sample(range(8), 2); a, b = random.choice(groups[g1]), random.choice(groups[g2])
       lines.append(f"  {a} --> {b}")
   open(out, "w").write("```mermaid\nflowchart LR\n" + "\n".join(lines) + "\n```\n")
   ```
   표본 248건 = 기본형 seed 0~3 × N∈{5,10,15,20,25,30}(24) + 기본형 seed 4~19 ×
   N∈{15,20,25,30,40}(80) + 허브·사슬·라벨형 각 seed 0~15 × N∈{10,20,30}(144).
5. 관찰(기본형 seed 2, N 증가): N=0 → 0.00초, 10 → 0.01초, 15 → 0.09초(그림), 20 → 60초
   초과(타임아웃). subgraph 없는 평평한 52노드 사슬과 "그룹 안 간선만"인 경우는 0.00초 —
   폭발의 축은 노드 수가 아니라 그룹을 가로지르는 간선 수다.
6. 관찰(표본 248건, 12초 타임아웃, 8병렬): 그림 128 / 폴백 19 / 타임아웃 101, 합계 1,559초.
   그림 128건 중 60건이 1초 초과, 그림의 높이는 중앙값 337행(최대 619행). 그림/폴백/타임아웃
   분할은 타임아웃 문턱 근처 건에서 실행마다 흔들린다(같은 건이 폴백↔타임아웃) — 이후
   비교는 "수정 전 그림으로 끝난 건의 결과 바이트"와 "시간 상한"만 기준으로 삼는다.
7. 관찰(`DG_DEBUG=1` stderr, seed 2·N=20): 시도 순서 `cap 30 LeftRight`(폭 303 > 118) →
   `cap 30 TopDown`(143) → `cap 30 TopDown fold`가 13회 넘게 반복되며 폭 133~154에서
   요지부동. 접기 1회마다 층 수 21 → 42 → 63 → 121 → 161 → 241 → … → 881, 가상 노드
   137 → 12,512개, 구간 201 → 12,576개, 접기 한 번의 배치 시간 3ms → 10초. 이 동안 이웃
   교환(`swap block` 로그)은 0건. 다른 표본(기본형 seed 17·N=30)에서는 폭이 *줄어드는*
   접기가 층을 45 → 90 → 180 → 280 → 382로 거의 배씩 늘린다(접기당 증가가 정체하지 않음).
8. 관찰(실사용 2번째 펜스): 라벨 폭 단계(30/22/16/12)마다 `TopDown fold` 접기 14회씩 총 56회,
   폭은 첫 접기 뒤(671 → 559) 한 번도 줄지 않고, 층은 매 접기 +9(11 → 137, 구간 211 →
   1,381), 총 배치 68회 뒤 폴백.

## Boundary Context
- **In scope**: `src/diagram/layout/graph.rs`의 `render()` — mermaid flowchart·state·class·
  ER, PlantUML(component·class·state), BPMN(XML·YAML·bizprocess)이 모두 이 함수로 그린다 —
  에서 폭에 안 들어가 재시도(방향 전환·층 접기·라벨 폭 단계)하는 동안의 시간. 층 접기로
  그룹 블록이 통째로 밀리는 경로는 상자형 그룹(flowchart subgraph, class namespace, state
  복합 상태, PlantUML package, bizprocess L3 상자)이 있는 그림에서만 생긴다(BPMN 레인은
  접기 대상이 아니고 ER은 그룹이 없다); 배치 한 번의 비용을 줄이는 변경은 모든 그림에
  적용되되 결과를 바꾸지 않는다.
- **Out of scope**: 페이저 스크롤 체감 지연(보고됐으나 이 세션은 비대화형 측정만 했고,
  `src/pager.rs`는 폭 변경·감시 갱신 때만 재렌더링하므로 별도 증거 없이는 다루지 않는다),
  메모리(측정상 문제 없음), 접기 규칙(어느 자식을 어디로 접는지)·폴백 판정·이웃 교환의
  결과를 바꾸는 변경(검토했으나 결과 퇴행이 실측돼 기각 — design.md·research.md),
  라벨 폭 단계 순서
