# Render Comparison 2 — bpmn-gateway-fixed-size (가로 바 유무 · 최소 폭)

## 정의
게이트웨이 마름모의 "모양·크기"를 사용자가 실물로 고르기 위해, 기존 후보 B·C(가로 바 `╱─╲`, 폭 5)와
새 후보 D·E(가로 바 없음, 대각선이 한 점에서 만나는 폭 3 마름모)를 같은 다섯 표본으로 나란히 그린 증거
자료다. 1차 비교는 `render-comparison.md`(현행·A·B·C), 분석·결론은 `research.md`·`decision-log.md`.

## 관찰 요약(2026-10-01, `cbfd774` 격리 worktree 프로토타입, 실험 후 worktree 삭제·본체 무변경)
- **핵심 비교 축은 "가로 바 있음(B/C, 폭 5) vs 가로 바 없음 + 최소 폭(D/E, 폭 3)"**이다. D(ASCII)와
  E(유니코드)는 같은 기하(`/\`·`<×>`·`\/` ↔ `╱╲`·`‹×›`·`╲╱`)에 글자만 다르다 — ASCII냐 유니코드냐는 부차적.
- **크기**: D/E는 기호 한 글자일 때 3×3(기호 폭 + 옆면 2), B/C는 5×3. 그림 폭도 준다 — 표본 2(LR 기본)
  현행 111 → B 105 → E-오른쪽 99 → E-아래 91, 표본 4(LR 분기) B 87 → E-오른쪽 81 → E-아래 77, 표본 5(협업)
  B 87 → E-오른쪽 85 → E-아래 84. 표본 3(TD 분기)은 층 폭이 태스크 상자에 묶여 51로 전부 같다.
- **폭 3의 기하적 한계**: 꼭짓점 쌍 `╱╲`(두 칸)가 홀수 폭의 가운데 열(기호 열)에 정확히 못 와서 반 칸
  어긋난다 — 왼쪽 붙임(기본, `╱╲` 위에 `‹×`)이든 오른쪽 붙임(`╱╲` 위에 `×›`)이든 어느 한쪽으로 치우친다
  (§보조 1). 기호가 두 글자(폭 4, 짝수)면 정확히 가운데에 온다(§보조 2). 가로 바를 없앤 대신 생긴 비용.
- **이름 위치**: D-아래/E-아래는 옛 C의 LR 빈틈(`‹ + ›                   ─╮`)을 고쳤다 — 간선이 마름모
  몸체에 바로 닿고 이름은 그 아래 along 여백에 남는다(`‹+›──────╮` / 아래 줄 `모든 사전 준비가 끝난 뒤`).
  TD에서는 이름을 출구 선 오른쪽 한 칸 띄워 아래 줄에 두어 선이 이름을 피해 간다(`│ OK?`). 남은 결함: LR에서
  이름이 둘 이상 줄이면 노드가 높아져 들어오는 선이 한 줄 꺾인다(`─╯ ╭▶‹+›`, 옛 C와 같음).
- **라벨 소실(요구사항 2.8)**: 점 고정 후보 전부(B·C·D·E)에서 LR 다중 출구 라벨 `예`가 사라진다(표본 4) —
  폭 3이 되어도 결과는 같다. 배치기 라벨 배치 문제라 도형 폭과 무관함이 재확인됐다.
- **이벤트와의 구분**: 이름 없는 `‹○›`/`<○>`는 `○ 시작`·`◉ 끝`과 옆면 글자·위아래 꼭짓점 줄로 구분된다
  (표본 1·2 끝부분). 단 폭 3이라 B의 `‹ ○ ›`보다 테두리가 얇아 멀리서 보면 글자 덩어리에 가깝다.
- **가독성 판단(선택은 하지 않음)**: E(`╱╲`/`‹×›`/`╲╱`)는 B보다 "마름모"보다는 "다이아몬드 글자 하나"처럼
  읽히고 작아서 눈에 덜 띈다; D(`/\`/`<×>`/`\/`)는 ASCII 슬래시가 셀 안에서 짧아 꼭짓점이 더 끊겨 보이고,
  옆면 `<`·`>`는 LR에서 화살촉 `▶`와 바로 붙는다(`──▶<×>`). B/C는 넓지만 테두리가 연속된 도형으로 읽힌다.
- 화살표 충돌(각주): LR에서 D의 `<`/`>`는 `Marker::OpenArrow`의 LR 글자와 같은 글자다(메시지 흐름·데이터
  연관 끝). 이번 다섯 표본에는 게이트웨이에 닿는 OpenArrow가 없어 직접 겹친 실물은 없다; `──▶<×>`에서
  `▶<`가 붙어 보이는 정도만 관찰됐다. E(`‹›`)는 해당 없음.

- 현행 바이너리: `main` `cbfd774` `target/release/dg`. 후보: 같은 커밋을 격리 `git worktree`에 체크아웃해
  `Shape::Gateway`(접점 오프셋 `point_anchor() -> Option<(dx, dy)>`, 배치기 `anchor_offset`·`along_pad`)를
  덧댄 프로토타입(4파일), 환경 변수 `DG_GW_GLYPHS=b|d|e`·`DG_GW_NAME=right|below_old|below`로 후보 전환.
- 공통 옵션 `-P -s none`. 폭·방향은 표본별 제목. 입력 XML은 `research.md` §입력 표본과 동일(`gw-basic`·
  `gw-split`·`collab`).
- 후보 정의 — B: `╱─╲`/`‹ × ›`/`╲─╱` 5×3, 이름 오른쪽 가운데 줄. C: B와 같되 이름 아래(옛 방식 — 노드

  간선이 마름모 몸체에 바로 닿고 이름은 along 여백에 두는 개선 방식. 접점은 전부 마름모 가운데 칸(B/C 열 2,
  D/E 열 1).
