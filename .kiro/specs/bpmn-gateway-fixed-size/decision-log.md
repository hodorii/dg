# 결정 기록 — bpmn-gateway-fixed-size

## 결정 — ⚠️ 잠정(아래 "bpmn.io 실물 비교" 이후 재확인 필요, 아직 최종 아님)
- **1차 선택(2026-09-30 오전)**: 후보 B — 게이트웨이 마름모를 고정 5×3(`╱─╲` / `‹ 기호 ›` /
  `╲─╱`)으로 그리고, 이름은 마름모 오른쪽에 구분선 없이 붙인다(`‹ × › OK?`).
- **기각**: 후보 A(기호 한 글자만, 이벤트 패턴 그대로) — 이름 없는 포괄 게이트웨이(`○`)가 시작
  이벤트(`○`)와 완전히 같은 글자가 되어 구분 불가(실물로 확인). 이 기각은 bpmn.io 비교 이후에도
  유효함.
- **보류로 전환**: 후보 C(이름을 마름모 아래) — 애초 기각 사유(LR 빈틈)는 실물로 확인됐지만,
  **실제 bpmn.io가 쓰는 방식이 바로 이것**임이 아래 절에서 드러나 재검토 대상이 됐다.

## 남은 결함(design 단계에서 반드시 해결)
가로 배치(LR)에서 출구가 둘 이상이고 각 출구에 라벨(예·아니오 등)이 있으면, 후보 B(및 C)
프로토타입은 라벨 하나를 잃는다. 현행은 둘 다 보인다. 이건 요구사항 2.8("출구 라벨 소실 금지")에
이미 불합격 조건으로 못박혀 있다 — 프로토타입 그대로는 design 승인 대상이 아니다.

## bpmn.io 실물 비교(2026-09-30, demo.bpmn.io 직접 확인)

이전 비교는 전부 우리 프로토타입끼리의 비교였다(A/B/C 모두 이쪽에서 상상한 후보). 사용자 지적대로
"진짜 bpmn.io가 어떻게 그리는지"를 직접 봐야 해서 `demo.bpmn.io`(공식 bpmn-js 모델러 데모)를 열어
기본 예시(시작 이벤트 → 태스크 → 배타 게이트웨이)를 실측했다.

```
 ⭕ ──▶ [ choose recipe ] ──▶ ◇(X)
hunger noticed                desired dish?
```
(실제 스크린샷: `/tmp/claude-chrome-screenshots-IOAhTq/screenshot-1790749913104-0.png`)

**직접 확인한 사실**:
- 게이트웨이 마름모는 **정사각형에 가까운 고정 크기**(가로≈세로, 태스크 박스보다 눈에 띄게
  작음) — 이건 "고정 크기"라는 방향 자체는 맞다는 근거.
- **이름은 마름모 오른쪽이 아니라 아래**에 놓인다(`desired dish?`가 마름모 밑, 가운데 정렬).
  이벤트도 마찬가지로 이름이 아래(`hunger noticed`가 원 밑).
- 태스크(라운드렉트)는 이름이 상자 **안** 가운데, 아이콘 표시는 이번 기본 예시에는 없었다(작은
  태스크 유형 아이콘은 왼쪽 위 모서리에 별도로 들어가는 게 bpmn.io의 일반적 관례로 알려져
  있으나 이번 확인 대상은 아니었다).

**이게 뜻하는 것 — 방금 확정한 결정과 부딪힌다**: 실물 bpmn.io는 "이름 아래" 방식이고, 이건
우리가 LR 빈틈 문제로 **기각한 후보 C**에 해당한다. 방금 선택한 **후보 B(이름 오른쪽)는
bpmn.io 실제 관례가 아니라 우리가 절충안으로 고른 것**이다. 정리하면:
- bpmn.io에 가장 가깝게 하려면 → C(이름 아래), 단 우리 프로토타입 LR에서 빈틈 결함이 있어 design
  단계에서 그 빈틈 자체를 없애는 배치를 새로 찾아야 함(단순 "아래에 붙이기"가 아니라 bpmn.io처럼
  간선이 이름을 피해서 지나가야 함 — 지금 프로토타입은 그걸 안 했다).
- 터미널 문자 격자 제약상 "이름 아래"가 실제로 더 어려운 이유: bpmn.io는 벡터 캔버스라 이름을
  얼마든지 좁은 폭으로 줄바꿈해 마름모 바로 아래 딱 붙일 수 있지만, dg는 고정폭 문자 칸이라
  긴 이름은 마름모보다 훨씬 넓어지고, 그 폭만큼 좌우로 뭔가(선·다음 노드)가 밀려나거나 겹친다 —
  이게 프로토타입 C에서 관찰된 빈틈의 근본 원인이다.
- **재검토 필요**: B를 그대로 밀고 갈지, C를 bpmn.io처럼 "간선이 이름 상자를 피해 지나가게"
  design에서 제대로 풀지 사용자 재확인이 필요하다 — 이 문서의 "결정"란은 아직 확정이 아니다.

## 관찰
- 세로형은 B가 확실히 더 깔끔하다 — 마름모가 전부 같은 크기, 예/아니오 라벨이 둘 다 보인다.
- 가로형은 B의 라벨 소실만 고치면(design 범위) 라운드렉트(태스크) 크기는 그대로 둬도 전체 그림이
  자연스럽게 어울린다 — 태스크 크기 정책(`bpmn-task-min-width`, 로드맵 별도 항목)은 이번 결정과
  별개로 급하지 않아 보인다.
