# Requirements — bpmn-model

## 정의
BPMN XML·YAML·`biz-process.md` 세 입력 문법이 하나의 렌더링 능력으로 모이도록,
세 파서가 공통으로 만들어 낼 BPMN 의미 모델(풀·레인·흐름 노드·흐름)을 정하고,
그 모델을 BPMN 구조 규칙으로 검증한 뒤 이미 구현된 레인 배치·BPMN 도형 어휘로
문자 그림을 그리는 기능이다. 파서 없이 손으로 만든 모델로만 검증한다.

## Boundary Context
- **In scope**: 풀·레인(중첩)·흐름 노드(이벤트·태스크·접힌 서브프로세스·호출
  활동·게이트웨이·데이터 객체·데이터 저장소·텍스트 주석)·흐름(시퀀스·default·
  메시지·연관·데이터 연관)·경계 이벤트 부착·방향·제목을 담는 모델, 모델의 BPMN
  구조 규칙 검증과 위반 시 거부, 모델 요소 → 기존 도형·표식·레인 관례 매핑,
  경계 이벤트의 v1 근사 렌더링, 가로/세로 방향, 세 파서가 공유할 종류 토큰
  어휘(BPMN XML 로컬 요소명 기준)와 그 도형 라벨, 다이어그램 언어 `bpmn`의
  판별·캡션·기존 폭 초과 폴백 규약 편입, 기존 mermaid·PlantUML 렌더링 결과 불변
- **Out of scope**: BPMN 다이어그램 교환 계층(BPMNDI — 좌표·크기·선 경로·`isHorizontal` 등
  다른 도구가 그린 모양; 모델은 프로세스 의미(참여자·레인·태스크·이벤트·게이트웨이·흐름)만
  담고 배치는 dg가 스스로 한다 — 사용자 결정 2026-09-26, 영구 제외), BPMN XML·YAML·
  `biz-process.md` 파서와 코드펜스 본문 문법
  (`bpmn-xml`·`bpmn-yaml`·`bizprocess-bpmn` — 이 스펙에서는 `bpmn` 코드펜스 본문이
  어떤 것이든 원문 코드블록으로 물러난다), 펼친 서브프로세스와 그 안의 노드 중첩·
  `ExpandPolicy`/`depth` 옵션(`bizprocess-bpmn`), 풀을 넘는 Group 아티팩트, 풀·레인
  자체를 메시지 흐름의 끝으로 쓰는 것(블랙박스 풀은 띠만 그려짐), 경계 이벤트를
  호스트 테두리에 실제로 붙이는 렌더링, 중간 이벤트 이중선, 새 도형·표식·레인
  배치 논리(`bpmn-shapes`·`bpmn-lane-layout` 완료분을 그대로 소비), 예제 문서

## Acceptance Criteria

### 1. 모델 검증 — 구조 규칙 위반은 거부
- 1.1: [시퀀스 흐름의 양끝이 서로 다른 풀에 속함] → [모델이 거부되고 오류에 그
  흐름 id가 포함된다; 그림은 나오지 않는다]
- 1.2: [시퀀스 흐름의 양끝이 같은 풀의 서로 다른 레인에 속함] → [정상 렌더링된다]
- 1.3: [메시지 흐름의 양끝이 같은 풀(또는 둘 다 풀 밖)에 속함] → [거부, 오류에
  흐름 id 포함]
- 1.4: [흐름·소속·부착이 존재하지 않는 id를 가리킴] → [거부, 오류에 그 id 포함]
- 1.5: [노드·풀·레인 id가 중복됨] → [거부, 오류에 중복 id 포함]
- 1.6: [시퀀스 흐름이 데이터 객체·데이터 저장소·텍스트 주석을 끝으로 가짐] →
  [거부, 오류에 흐름 id 포함]
- 1.7: [경계 이벤트가 중간 이벤트가 아니거나, 부착 대상이 태스크·서브프로세스·
  호출 활동이 아니거나, 소속을 따로 지정했는데 호스트와 다름] → [거부, 오류에
  이벤트 id 포함]
- 1.8: [위반이 여럿] → [첫 번째만 아니라 발견된 위반이 모두 보고된다]
- 1.9: [노드가 하나도 없는 모델(풀·레인만 선언돼 있어도)] → [거부되지 않되 그림도
  나오지 않는다(기존 빈 다이어그램과 같은 결과)]

### 2. 요소 → 도형 매핑(`bpmn-shapes`가 확정한 라벨 계약 그대로)
- 2.1: [시작/중간/종료 이벤트 + 이름] → [각각 `○`/`◎`/`●` 위치 글자가 붙은 이벤트
  상자, 종료는 굵은 테두리]
- 2.2: [이벤트에 트리거(message·timer·error·signal 등 12종) 지정] → [이름 아래
  둘째 줄에 `«message»`처럼 트리거 토큰이 흐리고 기울여 그려진다; 이름이 없으면
  트리거 줄만 있다]
- 2.3: [태스크 종류 user·service·script·manual·businessRule·send·receive] → [둥근
  상자 + 둘째 줄 `«user»`·`«service»`·…·`«businessRule»`; 종류 없음이면 둘째 줄
  없음]
- 2.4: [접힌 서브프로세스] → [아래 테두리 가운데 `[+]`가 있는 둥근 상자]
- 2.5: [호출 활동] → [둥근 상자 + 둘째 줄 `«call»`]
- 2.6: [게이트웨이 exclusive·parallel·inclusive·complex·eventBased + 이름] →
  [마름모 안 `× 이름`·`+ 이름`·`○ 이름`·`* 이름`·`◎ 이름`; 이름이 없으면 기호만]
- 2.7: [데이터 객체 / 데이터 저장소 / 텍스트 주석] → [각각 직사각형 + 둘째 줄
  `«data»` / 원통 / 점선 상자]

### 3. 흐름 → 선 매핑
- 3.1: [시퀀스 흐름 + 조건 라벨] → [실선 + 도착 쪽 채운 화살촉, 라벨은 선 위에]
- 3.2: [default 시퀀스 흐름] → [3.1에 더해 출발 쪽 꼬리에 `╱`]
- 3.3: [메시지 흐름] → [점선 + 출발 쪽 `○` 꼬리 + 도착 쪽 열린 화살촉]
- 3.4: [연관] → [점선, 표식 없음]
- 3.5: [데이터 연관] → [점선 + 도착 쪽 열린 화살촉]

### 4. 풀·레인 배치
- 4.1: [풀 둘 이상 선언] → [각 풀이 선언 순서대로 나란한 최상위 띠로 그려지고 제목이
  배너에 쓰인다]
- 4.2: [풀 안에 레인, 레인 안에 하위 레인] → [부모 띠 안에 자식 띠가 선언 순서대로
  중첩된다]
- 4.3: [노드가 하나도 없는 풀·레인(블랙박스 풀 포함)] → [띠와 제목이 그대로
  그려지고 사라지지 않는다]
- 4.4: [풀이 하나도 없는 모델] → [띠 없이 기존 평면 그래프처럼 그려진다]
- 4.5: [풀에 소속되지 않은 노드와 풀이 섞임] → [노드는 띠 밖에 그려지고 패닉이
  없다]

### 5. 경계 이벤트 v1 근사
- 5.1: [중간 이벤트가 태스크에 부착됨] → [이벤트가 호스트와 같은 레인 안 호스트
  바로 다음 층에 놓이고, 호스트에서 이벤트로 표식·라벨 없는 점선이 이어진다]
- 5.2: [경계 이벤트에서 나가는 시퀀스 흐름] → [3.1 규칙대로 실선 화살로 이어진다]

### 6. 방향·언어 판별·캡션·폴백
- 6.1: [방향 지정 없음 또는 가로(horizontal)] → [흐름이 왼쪽→오른쪽으로 진행하고
  풀 띠가 위아래로 쌓인다(BPMN 기본 관례)]
- 6.2: [세로(vertical) 지정] → [흐름이 위→아래, 풀 띠가 좌우로 나란하다]
- 6.3: [명령줄·환경 변수의 방향 옵션 지정] → [모델의 방향보다 옵션이 우선한다(기존
  다이어그램과 같은 우선순위)]
- 6.4: [지정 폭 초과] → [기존 규약(반대 방향 재시도 → 라벨 축소 → 원문 코드블록)
  그대로 따른다]
- 6.5: [모델에 제목이 있음] → [기존 그래프 제목 규약대로 그림 첫 줄 위에 굵게
  쓰인다]
- 6.6: [코드펜스 언어 `bpmn` / 파일 확장자 `.bpmn` / 명령줄 `--lang bpmn`] → [다이어
  그램 언어가 `bpmn`으로 판별된다]
- 6.7: [모델이 렌더링됨] → [캡션이 풀이 둘 이상이면 `◈ bpmn · collaboration`, 아니면
  `◈ bpmn · process`이다]
- 6.8: [이 스펙 시점의 `bpmn` 코드펜스(파서 없음)] → [어떤 본문이든 패닉 없이
  원문 코드블록으로 물러나고, 마크다운 문서의 나머지는 정상 렌더링된다]

### 7. 공유 어휘 토큰(세 파서의 SSoT)
- 7.1: [태스크·이벤트 트리거·게이트웨이 종류마다] → [BPMN XML 로컬 요소명 토큰
  (`userTask`·`messageEventDefinition`·`exclusiveGateway` 등)이 하나씩 있고,
  토큰 → 종류 → 토큰이 원문 그대로 되돌아온다]
- 7.2: [모르는 토큰] → [종류로 해석되지 않는다(오류로 남겨 파서가 진단하게 함)]
- 7.3: [항상] → [7.1의 토큰과 2.2·2.3·2.6의 라벨 문자열은 한 표에서만 나온다(같은
  값을 두 곳에 적지 않는다)]

### 8. 회귀·안전
- 8.1: [항상 + mermaid·PlantUML 코드펜스] → [렌더링 결과가 이 기능 이전과 바이트
  단위로 동일하다]
- 8.2: [항상] → [자기 자신으로 가는 흐름, 순환, 이름 없는 노드, 3단 중첩 레인,
  경계 이벤트 여러 개, 가로·세로 어느 조합에도 패닉이 없다]
- 8.3: [풀 2개(레인 2개 포함)·시작/종료 이벤트·`«user»`/`«service»` 태스크·XOR
  게이트웨이·default 흐름·메시지 흐름·경계 오류 이벤트를 섞은 손으로 만든 모델]
  → [폭 100 안에서 렌더링되고 1~6의 관례가 한 그림 안에서 모두 보인다]
