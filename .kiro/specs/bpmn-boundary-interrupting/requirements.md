# 요구사항 정의서 - bpmn-boundary-interrupting

## 정의
BPMN 다이어그램을 터미널에서 읽는 사용자가 경계 이벤트가 액티비티를 중단시키는지 아닌지를 그림만 보고 구분하도록, 경계 이벤트의 방해 여부를 입력에서 읽어 방해와 비방해를 다르게 그리는 경계 이벤트 표기 기능이다.

## 범위
- **포함**: XML과 YAML 입력의 경계 이벤트 방해 여부 읽기(1), 방해와 비방해 경계 이벤트의 구분 표기(2), 방해 여부와 트리거의 조합 검사(3).
- **제외**: 순수 ASCII 출력 모드, 노드 폭 고정 패딩, 새 입력 문법(mermaid 변환 포함), 경계 이벤트를 호스트 테두리 위에 올리는 배치, bizprocess 입력의 비방해 표현(bizprocess가 만드는 오류 경계 이벤트는 항상 방해).
- **인접 기대**: 흐름 종류별 선과 표식은 `bpmn-flow-kind-notation` 그대로다. 파선은 메시지 흐름, 점선은 연결과 데이터 연결이 쓰므로 비방해 구분에 선 무늬를 쓰지 않는다(사용자 결정: 식별성 우선, 선 무늬는 의미 충돌로 제외). 이벤트 위치 글자(시작 `○`, 중간 `◎`, 종료 `◉`)와 트리거 둘째 줄(예: `«timer»`)은 `bpmn-event-shape-notation` 그대로다.

## 요구사항

### 1. 경계 이벤트 방해 여부 읽기
disjoint:

| ID | 입력 | 사용자가 쓴 값 | 결과 |
|---|---|---|---|
| 1.1 | XML `boundaryEvent` | `cancelActivity` 없음 또는 `"true"` | 방해 |
| 1.2 | XML `boundaryEvent` | `cancelActivity="false"` | 비방해 |
| 1.3 | YAML `kind: boundaryEvent` | `cancel_activity` 없음 또는 `true` | 방해 |
| 1.4 | YAML `kind: boundaryEvent` | `cancel_activity: false` | 비방해 |

- 1.5: [XML `cancelActivity` 값이 `true`, `false` 외의 값] 원문 코드블록으로 물러난다.
- 1.6: [YAML `cancel_activity` 값이 불리언이 아님, 또는 `boundaryEvent`가 아닌 노드에 `cancel_activity`가 있음] 원문 코드블록으로 물러난다. 기존 `attached_to` 오용과 같은 방식이다.

### 2. 방해와 비방해 경계 이벤트를 다르게 그리기
- 2.1: [방해 경계 이벤트] 이 기능 전과 같은 모양으로 그려진다(중간 이벤트 글자 `◎`, 호스트에서 이어지는 실선).
- 2.2: [비방해 경계 이벤트] 이벤트 자리에서 방해와 다른 글자로 그려지고, 그 글자는 다른 이벤트 위치 글자와 게이트웨이 기호(`○`, `◎`, `◉`, `×`, `+`, `*`)와도 다르다.
- 2.3: [방해와 비방해가 한 다이어그램에 있음] 이름과 트리거 줄을 가려도 이벤트 글자만으로 둘이 구분된다.
- 2.4: [비방해 경계 이벤트] 호스트에서 이벤트로 이어지는 선과 이벤트에서 나가는 시퀀스 흐름은 실선이다(파선, 점선 아님).
- 2.5: [가로, 세로 배치] 2.1~2.4가 두 방향 모두에서 성립한다.

### 3. 방해 여부와 트리거 조합 검사
BPMN 2.0.2에서 오류와 취소 경계 이벤트는 항상 방해다.

- 3.1: [비방해 + 트리거가 오류 또는 취소] 원문 코드블록으로 물러난다. 기존 경계 이벤트 규칙 위반과 같은 방식이다.
- 3.2: [비방해 + 그 밖의 트리거 또는 트리거 없음] 2.2대로 그려진다.

### 4. 기존 동작 유지
- 4.1: [항상] 비방해 경계 이벤트가 없는 입력의 렌더링 결과는 이 기능 전과 바이트 단위로 같다.
- 4.2: [항상] 이 기능이 새로 그리는 글자는 모두 Noto Sans Mono CJK 커버리지 안의 한 칸 폭 글자다.
