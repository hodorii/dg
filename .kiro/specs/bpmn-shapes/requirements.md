# Requirements — bpmn-shapes

## 정의
BPMN 프로세스를 문자 그림으로 그려야 하는 후속 스펙(`bpmn-model` 이후)을 위해,
기존 그래프 배치기의 노드 모양·간선 표식 어휘에 BPMN 고유 도형(이벤트 세 종류,
접힌 서브프로세스)과 default 흐름 표식을 더하고, 기존 모양(마름모·둥근 상자·
`«스테레오타입»` 둘째 줄)으로 나머지 BPMN 요소를 그리는 관례를 확정하는 기능이다.
파서 없이 손으로 만든 그래프로만 검증한다.

## Boundary Context
- **In scope**: 시작·중간·종료 이벤트 노드 모양(위치 구분 글자 + 종료의 굵은
  테두리), 접힌 서브프로세스 노드 모양(아래 테두리의 `[+]`), default 흐름의
  빗금 꼬리 표식, **태스크(모든 하위 종류)는 기존 둥근 상자 그대로**(사용자 확정
  2026-09-25 — 폭·글자 겹침 같은 구체적 구현 문제가 없는 한 바꾸지 않음),
  이벤트·서브프로세스·태스크 노드의 `«…»` 둘째 줄
  (트리거·태스크 종류)이 흐리고 기울여 그려짐, 게이트웨이(기존 마름모) 라벨의 종류
  기호 관례와 그 기호의 기본 CJK 모노 폰트 커버리지, 기존 그래프의 렌더링 결과 불변
- **Out of scope**: 중간 이벤트의 이중선 테두리(`bpmn-support/research.md`가
  후순위로 미룸 — 위치 구분 글자로 충분), 경계 이벤트를 호스트 태스크 테두리에
  붙이는 렌더링(v1은 인접 노드 + 점선 근사, `bpmn-model`이 적용), 데이터 객체의
  접힌 모서리 도형(기존 `Rect` + `«data»`로 대체), 이벤트 트리거 아이콘 글자
  (✉·◷·⚡ 등 — 폰트 커버리지 문제, `«이름»` 텍스트로 대체), BPMN 의미 계층·
  검증·변환·`render()` 배선(`bpmn-model`), XML·YAML·`biz-process.md` 파서와 코드펜스
  언어·CLI 옵션·예제 문서(`bpmn-yaml`·`bpmn-xml`·`bizprocess-bpmn`), 레인 배치
  (`bpmn-lane-layout`, 완료됨 — 이 스펙은 레인 논리를 건드리지 않음)

## Acceptance Criteria

### 1. 이벤트 노드
- 1.1: [시작 이벤트 노드 + 이름 한 줄] → [둥근 모서리 상자 안, 이름 왼쪽에 `○`이
  같은 줄에 그려지고, 테두리는 기존 둥근 상자와 같은 가는 선이다]
- 1.2: [중간 이벤트 노드] → [1.1과 같되 위치 글자가 `◎`이다]
- 1.3: [종료 이벤트 노드] → [위치 글자가 `●`이고 테두리 전체가 굵은 선(`━`·`┃`)이며,
  가는 선 이벤트와 한눈에 구분된다]
- 1.4: [이벤트 노드의 세로 크기] → [이름 줄 수가 같은 기존 둥근 상자 노드와 높이가
  같다(위치 글자가 줄을 추가하지 않는다)]
- 1.5: [이벤트 노드에 간선이 드나듦(위→아래·왼쪽→오른쪽)] → [선과 화살촉이 기존
  노드와 같은 규칙으로 테두리 바로 바깥 칸에 붙는다]
- 1.6: [이름이 없는 이벤트 노드(예: `done: endEvent`처럼 라벨을 안 쓴 경우, 본문
  줄 없음)] → [위치 글자만 든 한 줄 높이 본문의 상자로 그려지고 패닉이 없다]

### 2. 접힌 서브프로세스 노드
- 2.1: [접힌 서브프로세스 노드] → [기존 둥근 상자와 같은 테두리·본문 배치에, 아래
  테두리 가운데에 `[+]`가 테두리 선을 대신해 그려진다]
- 2.2: [접힌 서브프로세스 노드에서 아래(위→아래 방향)로 간선이 나감] → [`[+]`가
  선에 덮여 지워지지 않는다]
- 2.3: [배치기가 노드를 측정값보다 넓게 늘림(교차축 정렬)] → [`[+]`가 늘어난 아래
  테두리의 가운데에 온다]

### 3. 태스크 모양과 `«…»` 둘째 줄(트리거·태스크 종류)
- 3.1: [이벤트 노드 이름 아래 둘째 줄이 `«timer»`처럼 `«`로 시작함] → [둘째 줄이
  테두리 안 이름 아래에 흐리고 기울인 글씨로 그려지고, 이름 줄은 굵게 유지된다]
- 3.2: [접힌 서브프로세스·둥근 상자(태스크) 노드의 둘째 줄이 `«`로 시작함] → [3.1과
  같은 흐림·기울임이 적용된다]
- 3.3: [둘째 줄이 없는 이벤트·서브프로세스·태스크 노드] → [둘째 줄 자리가 비지
  않고 이름 한 줄 높이로 그려진다]
- 3.4: [태스크 노드(user·service·script·manual·business-rule·send·receive 어떤
  종류든, 예: `userTask 주문 검토`·`serviceTask 품절 안내 발송`)] → [모양은 기존
  둥근 상자이고, 종류는 둘째 줄 `«user»`·`«service»` 등으로만 구분된다 — 종류별
  새 모양이 없다]

### 4. default 흐름 표식
- 4.1: [간선 꼬리 표식이 빗금 + 위→아래 방향] → [출발 노드 테두리 바로 아래 선 칸에
  `╱` 한 글자가 놓인다]
- 4.2: [간선 꼬리 표식이 빗금 + 왼쪽→오른쪽 방향] → [출발 노드 테두리 바로 오른쪽
  선 칸에 `╱` 한 글자가 놓인다]
- 4.3: [빗금 꼬리 + 화살촉 머리 + 간선 라벨] → [화살촉·라벨은 기존 규칙대로 그려지고
  라벨이 빗금을 덮어쓰지 않는다]

### 5. 게이트웨이 라벨 관례(기존 마름모 재사용)
- 5.1: [마름모 노드 라벨이 `× 승인?`·`+ 병렬`·`○ 선택`·`* 복합`·`◎ 이벤트` 중 하나] →
  [기호와 이름이 마름모 안 한 줄에 그대로(흐림·기울임 없이) 그려진다]
- 5.2: [항상] → [5.1의 다섯 기호와 1.1~1.3의 위치 글자, 4.1의 빗금은 모두 기본 CJK
  모노스페이스 폰트(Noto Sans Mono CJK)의 커버리지 안에 있어 폰트 폴백이 일어나지
  않는다]

### 6. 회귀·안전
- 6.1: [항상 + 새 모양·새 표식을 쓰지 않는 그래프] → [렌더링 결과가 이 기능 이전과
  바이트 단위로 동일하다]
- 6.2: [항상] → [새 모양·새 표식의 어떤 조합(이름 없음·한 글자, 여러 줄 본문,
  레인 안 배치, 양방향)에도 패닉이 없다]
- 6.3: [레인 2개·시작/종료 이벤트·`«user»`/`«service»` 태스크·`×` 게이트웨이·조건
  라벨 흐름 2개를 섞은, 손으로 만든 그래프] → [폭 100 안에서 렌더링되고, 위 1~5의
  관례가 한 그림 안에서 모두 보인다]
