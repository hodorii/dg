# Implementation Plan — bpmn-shapes

## 정의
기존 그래프 배치기의 노드 모양·간선 표식 어휘에 BPMN 이벤트·접힌 서브프로세스·
default 흐름 빗금을 더하고, 게이트웨이·태스크·`«…»` 둘째 줄 관례를 테스트로 고정하는
기능이다. 파서 없이 손으로 만든 그래프 단위 테스트로만 검증한다.

    렌더링해 스크래치 디렉터리에 저장(5.1의 diff 기준)
  - DONE: 예제 파일마다 기준 출력 파일이 하나씩 있고, 같은 명령을 다시 돌려도 같은

- [x] 1.2 (P) 스타일까지 보는 도형 테스트 헬퍼와 기존 어휘 관례 테스트
  - 도형 테스트에 글자와 스타일(굵음·흐림·기울임)을 함께 돌려주는 헬퍼를 더한다
    (기존 글자만 보는 헬퍼는 그대로 둠)
  - 태스크 = 둥근 상자 + 둘째 줄 `«user»`가 흐리고 기울여지고 이름 줄은 굵은지,
    한 줄 본문이면 높이가 이름 한 줄 기준인지 확인(사용자 확정: 태스크 종류별 새
    모양 없음)
  - 게이트웨이 다섯 라벨(`× 승인?`·`+ 병렬`·`○ 선택`·`* 복합`·`◎ 이벤트`)이 마름모
    가운데 줄에 원문 그대로, 기호가 흐려지지 않고 그려지는지 확인
  - 게이트웨이 기호 다섯 개·이벤트 위치 글자 세 개·빗금의 코드포인트가 design
    §Key Decisions의 커버리지 허용 목록(research.md 실측 표) 안에 있는지 상수 대조
  - DONE: `draw_runs(Shape::Round, [["주문 검토", "«user»"]])`의 둘째 줄 run이
    `dim && italic`, 첫 줄 run이 `bold`; 다섯 게이트웨이 라벨의 가운데 줄이 라벨
    원문을 포함하고 기호 run이 `!dim && !italic`; 코드포인트 허용 목록 테스트 통과
  - _Requirements: 3.2, 3.4, 5.1, 5.2_
  - _Difficulty: low_
  - _Boundary: layout::shape_

- [x] 2. 새 도형(같은 파일 — 순차)
- [x] 2.1 이벤트 모양(시작·중간·종료)
  - 이벤트 위치(시작/중간/종료)를 담는 모양 변형을 어휘에 더하고, 측정은 "둥근 상자
    + 위치 글자 두 칸"(본문이 비어도 한 줄 본문 확보), 그리기는 시작·중간이 가는
    둥근 테두리, 종료가 각진 굵은 테두리(design §Key Decisions "종료 이벤트" 결정),
    위치 글자 `○`/`◎`/`●`를 본문 첫 줄 왼쪽에 강조색으로, 본문은 기존 칸 그리기
    재사용(둘째 줄 `«timer»` 흐림은 자동)
  - DONE: 단위 테스트에서 시작 "Go" → `["╭──────╮", "│ ○ Go │", "╰──────╯"]`, 중간은
    같은 줄에 `◎`, 종료 → `["┏━━━━━━┓", "┃ ● Go ┃", "┗━━━━━━┛"]`, 본문 없음 →
    `["╭────╮", "│ ○  │", "╰────╯"]`에 패닉 없음, `["Go", "«timer»"]`는 높이 4에 둘째
    줄 run이 `dim && italic`·첫 줄 `bold`, 한 줄 본문은 높이 3
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.6, 3.1, 3.3_
  - _Difficulty: mid_
  - _Boundary: diagram::ir, layout::shape_
  - _Depends: 1.2_

- [x] 2.2 접힌 서브프로세스 모양
  - 모양 변형을 어휘에 더하고, 측정·테두리·본문은 둥근 상자와 같게, 본문을 그린
    뒤 아래 테두리 줄 가운데에 `[+]`를 글자로 덮어쓴다(design "Subprocess `[+]`" 행)
  - DONE: 단위 테스트에서 "Sub" → `["╭─────╮", "│ Sub │", "╰─[+]─╯"]`; 최소 폭을
    측정값 + 4로 늘려 그리면 `[+]`가 늘어난 아래 줄의 가운데(왼쪽·오른쪽 `─` 수가
    같거나 1 차이); 둘째 줄 `«call»`이 `dim && italic`
  - _Requirements: 2.1, 2.3, 3.2_
  - _Difficulty: low_
  - _Boundary: diagram::ir, layout::shape_

- [x] 3. 새 표식
- [x] 3.1 default 흐름 빗금 꼬리 표식
  - 표식 어휘에 빗금을 더하고 표식 글자 표에 방향 무관 `╱` 한 글자로 등록(기존
    `Circle`/`Cross`와 같은 패턴). 배치기의 다른 함수는 건드리지 않는다
  - DONE: 단위 테스트에서 네 방향 조합 모두 `['╱']`; TB `a --빗금--> b` 렌더링에서
    a 테두리 바로 아래 줄의 출발 열이 `╱`; LR에서 a 오른쪽 바로 다음 칸이 `╱`;
    LR + 라벨 "no" + 화살촉 머리에서 라벨이 `╱` 다음 칸부터 시작하고 `▶`가 b에 붙음
  - _Requirements: 4.1, 4.2, 4.3_
  - _Difficulty: mid_
  - _Boundary: diagram::ir, layout::graph_
  - _Depends: 2.2_

- [x] 4. 배치기 안에서의 경계 동작
- [x] 4.1 새 도형의 접점·`[+]` 보존·패닉 없음
  - 배치기 `render()` 테스트로 새 도형이 기존 접점 규칙을 따르는지 고정한다;
    드러나는 결함은 이 태스크 안에서 고친다
  - DONE: 단위 테스트에서 (a) TB 시작 이벤트→둥근 상자→종료 이벤트 사슬의 화살촉이
    각 도착 노드 테두리 바로 위 줄에 있고 굵은 테두리 노드에도 선이 붙음, LR도 동일,
    (b) TB 서브프로세스→상자에서 `[+]`가 출력 후에도 남고 그 아래 줄에 선이 있음,
    (c) 이름 없는 이벤트·한 글자·세 줄 본문·레인 안 이벤트/서브프로세스·양방향·
    빗금 양끝 조합에 패닉 없음
  - _Requirements: 1.5, 2.2, 6.2_
  - _Difficulty: mid_
  - _Boundary: layout::graph_
  - _Depends: 2.1, 2.2, 3.1_
