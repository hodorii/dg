# Implementation Plan — bpmn-message-flow-participant-endpoint

## 정의
블랙박스 풀과 메시지를 주고받는 협업을 그리기 위해, 메시지 흐름의 끝으로 최상위 참여자 id를
허용하고 그 끝을 참여자 띠의 그룹 닻에 잇는 수정이다. 파서 없이 손으로 만든 모델 테스트로만
검증한다.

- [ ] 1. 재현 테스트 작성(수정 전 실패해야 함)
- [ ] 1.1 (P) 검증이 참여자 끝 메시지 흐름을 받아들이는지 재현
  - bugfix.md 재현 절차 2의 모델(블랙박스 풀 `고객` → 다른 풀 요소로 가는 메시지 흐름)이 통과하는지,
    양끝이 서로 다른 참여자 id인 모델이 통과하는지, 참여자 id + 그 참여자 안 요소가 "같은 풀 안
    메시지 흐름" 위반(흐름 id 포함)으로 거부되는지 단정한다
  - DONE: 세 단정이 수정 전 코드에서 `UnknownReference`(흐름 id → 참여자 id)로 **실패**함을 확인(1.1,
    1.3, 1.4)
  - _Requirements: 1.1, 1.3, 1.4, 2.1, 2.3, 2.4_
  - _Difficulty: low_
  - _Boundary: bpmn::validate_

- [ ] 1.2 (P) 변환이 참여자 끝 메시지 흐름을 간선으로 남기는지 재현
  - 같은 모델을 검증 없이 변환해 간선이 2개이고, 메시지 간선이 점선·`○` 꼬리·열린 화살촉·라벨
    `주문`이며, 참여자 쪽 끝이 `고객` 그룹 안의 보이지 않는 닻 노드이고, 그 그룹의 보이지 않는 노드가
    정확히 하나인지 단정한다
  - DONE: 수정 전 코드에서 간선 1개로 **실패**함을 확인(1.2)
  - _Requirements: 1.2, 2.2_
  - _Difficulty: low_
  - _Boundary: bpmn::lower_

- [ ] 2. 불변 동작 테스트(수정 전에도 통과해야 함)
- [ ] 2.1 요소만 끝이 될 수 있는 흐름과 레인 끝의 거부 확인
  - 시퀀스·연관·데이터 연관 흐름의 한쪽 끝을 참여자 id로 둔 모델, 메시지 흐름의 한쪽 끝을 레인 id로 둔
    모델이 각각 `UnknownReference`(흐름 id → 그 id)로 거부되는지 단정한다
  - DONE: 새 단정 두 건이 수정 전 코드에서 통과하고, 기존 `validate`·`lower`·`bpmn::tests` 스위트
    (같은 풀 안·풀 밖 메시지 흐름 거부, 요소 사이 메시지 선 모양, 빈 풀 자리표시 하나, 모르는 id
    건너뜀, 노드 없는 모델 `Ok`/`None`)가 전량 통과함을 확인(3.1~3.7)
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7_
  - _Difficulty: low_
  - _Boundary: bpmn::validate_

- [ ] 3. 수정 적용
- [ ] 3.1 최상위 참여자 id 정확 일치 조회

    id는 `None`
  - DONE: 단위 테스트에서 참여자 id → `Some(인덱스)`, 그 참여자의 레인 id·하위 레인 id·모르는 id →

- [ ] 3.2 (P) 검증 — 메시지 흐름의 끝으로 참여자 허용, 풀 사이 규칙은 그대로
  - design §수정 방식 `validate.rs`: 참조 해석에서 메시지 흐름의 끝만 요소 또는 최상위 참여자를
    허용하고, 끝의 풀 인덱스를 구할 때 참여자 끝은 그 참여자 자신으로 본다. 시퀀스·연관·데이터 연관
    흐름의 끝 조건과 "같은 풀 안 메시지 흐름" 규칙은 손대지 않는다
  - DONE: 1.1의 재현 테스트 세 단정이 통과로 바뀌고 2.1의 불변 테스트가 계속 통과
  - _Requirements: 2.1, 2.3, 2.4, 3.1, 3.2, 3.3_
  - _Difficulty: mid_
  - _Boundary: bpmn::validate_
  - _Depends: 3.1_

- [ ] 3.3 (P) 변환 — 참여자 끝을 그룹 닻에 잇고 자리표시와 겹치지 않게
  - design §수정 방식 `lower.rs`: 흐름의 끝을 노드에서 못 찾으면 메시지 흐름이고 최상위 참여자일 때만
    그 참여자 그룹의 닻(`ir::Graph::group_anchor`)으로 해석, 아니면 종전대로 건너뜀; 흐름 추가를 빈
    그룹 자리표시 추가보다 먼저 실행해 닻이 자리표시를 겸하게 한다. 선 종류·표식·라벨 표는 그대로
  - DONE: 1.2의 재현 테스트가 통과로 바뀌고(간선 2개, 닻 노드 하나), 기존 `lower` 테스트(빈 풀
    자리표시 하나, 모르는 id 건너뜀 등)가 계속 통과
  - _Requirements: 2.2, 3.4, 3.5, 3.6_
  - _Difficulty: mid_

  - _Depends: 3.1_
