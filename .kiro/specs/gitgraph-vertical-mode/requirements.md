# Requirements — gitgraph-vertical-mode

## 정의
좁은 터미널에서 gitGraph를 읽으려는 사용자를 위해, 기존 가로 모드(브랜치=행, 시간=열)에 더해
세로 모드(브랜치=열, 시간=행)를 추가하는 기능이다.

## Boundary Context
- **In scope**: gitGraph 헤더(`gitGraph TB:`/`BT:`)의 방향 파싱, 기존 `DiagramOptions.direction`(CLI `--direction`, `%% dg: direction=` 지시자)에 의한 강제, 세로 배치 렌더링(트랙 열, 커밋 행), 폭 초과 시 반대 방향 재시도
- **Out of scope**: 가로 모드 자체의 변경, 브랜치 색상 구분(별도 스펙 `gitgraph-branch-distinction`), PlantUML gitGraph(존재하지 않음)

## Acceptance Criteria

### 1. 방향 판별
- 1.1: [`gitGraph TB:` 또는 `gitGraph TD:` 헤더] → 세로 모드로 렌더링됨
- 1.2: [`gitGraph LR:` 헤더 또는 방향 지정 없음] → 기존 가로 모드로 렌더링됨(하위 호환)
- 1.3: [CLI `--direction tb` 또는 `%% dg: direction=tb` 지시자, 소스 헤더는 `LR`] → 지시자가 헤더보다 우선해 세로 모드로 렌더링됨(다른 그래프형과 같은 계약)

### 2. 세로 배치
- 2.1: [세로 모드, `commit` 여러 개] → 한 트랙(열) 안에서 커밋이 등장 순서대로 위에서 아래로 배치됨
- 2.2: [세로 모드, `branch` 정의] → 새 트랙 열이 추가되고 이름이 그 열 위 머리글에 표시됨
- 2.3: [세로 모드, `merge` 정의] → 두 트랙 열 사이에 가로 연결선이 표시됨

### 3. 폭 계약
- 3.1: [가로 모드로는 폭 초과, 세로 모드로는 들어감] → 반대 방향(세로)으로 재시도되어 렌더링됨(기존 그래프형의 "안 맞으면 반대 방향" 계약과 동일)
- 3.2: [세로 모드로도 폭 초과] → 이름·아이디를 줄여 가며 재시도하고, 그래도 안 되면 원문 코드블록으로 대체됨(패닉 없음)

### 4. 회귀
- 4.1: [기존 가로 모드 테스트] → 방향을 지정하지 않은 기존 입력은 그대로 가로 모드로 렌더링되어 기존 테스트가 통과함
- 4.2: [항상] → 어떤 입력에도 비정상 종료(패닉)하지 않음
