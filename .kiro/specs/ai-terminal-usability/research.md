# Research Log - ai-terminal-usability

## Summary
- **Feature**: `ai-terminal-usability`
- **Discovery Scope**: Extension (`main.rs`, `pager.rs`, `watch.rs`, `links.rs` 기존 표면 조사, 코드 변경 없음)
- **Method**: 소스 읽기, 릴리스 바이너리(`target/release/dg`, 0.4.0) 직접 실행, tmux 3.8 분리 세션에서 폭 변경과 파일 변경 재현, tmux 소스 확인
- **Key Findings**:
  - 마찰 여섯 건을 재현 또는 소스로 확인했다. 가장 큰 것은 "그릴 수 없을 때 원문으로 대체하면서 종료 코드 0과 빈 stderr로 끝난다"는 점이다(F1).
  - 폭, 감시, 종료 코드 오류(파일 없음)는 기대대로 동작했다. 이 영역은 개선 항목이 아니다(아래 "문제 없음").
  - herdr 패널에서 실제로 돌려 보지는 못했다. 사용자 세션을 건드리지 않으려고 tmux만 썼다(Unverified 절 참고).

## 마찰 목록

우선순위는 영향(AI 협업 흐름이 막히는 정도) x 확실성(재현 여부)으로 매겼다.

### F1. 그리기 실패가 신호 없이 원문으로 대체됨 (우선순위 높음)
- **재현**: 잘못된 mermaid(`notadiagram foo`)가 든 문서를 `dg -P -s none`으로 렌더링.
- **관찰**: 종료 코드 0, stderr 0바이트. 화면에는 성공 표지 `◈ mermaid · flowchart` 대신 코드블록 표지 `╭─ mermaid ─`만 달라진다.
- **관찰 2**: 문법이 일부만 틀린 입력(`A --> ` 뒤에 `???`)은 노드 하나(`A`)만 그린 채 성공으로 보인다. 부분 파싱 사실도 알려 주지 않는다.
- **영향**: AI가 마크다운을 고친 뒤 "다이어그램이 그려졌는지"를 알려면 출력의 첫 글자 모양(`◈` 대 `╭`)을 파싱해야 한다. 표지 글자가 바뀌면 깨진다.
- **경계 후보**: 사람용 출력 포맷은 건드리지 않고 별도 표면(종료 코드 또는 stderr 요약 또는 전용 옵션)으로 분리한다(brief Boundary Candidates).

### F2. 좁은 창에서 다이어그램이 조용히 원문이 됨 (우선순위 높음)
- **재현**: `examples/sequence.md` 첫 블록을 `-w`를 바꿔 렌더링.
- **관찰**: 64칸까지 그려지고 63칸부터 원문으로 대체된다(64칸은 `◈` 표지, 63칸은 `╭─` 표지).
- **관찰 2**: tmux 40칸 창에서 같은 문서를 열면 원문 코드블록이 줄바꿈된 채 보인다. 상태 표시줄에는 "폭이 모자라 원문으로 보인다"는 안내가 없다.
- **영향**: 분할 화면의 좁은 쪽 창에서 보던 사용자는 다이어그램 문법이 틀린 것인지 폭이 모자란 것인지 구분할 수 없다. F1과 같은 근본 원인(대체 사유 미표시).
- **참고**: 폭이 남는 만큼 라벨 폭을 줄여 다시 시도하는 로직은 이미 있다(`layout/graph.rs`). 개선 대상은 배치 품질이 아니라 "대체되었다는 사실과 사유의 표시"다(배치 알고리즘 품질은 Out of Boundary).

### F3. print 모드 감시(`-P -W`)가 프레임 구분 없이 이어 붙임 (우선순위 중간)
- **재현**: `dg -P -W -s none file.md`를 파일로 리다이렉트하고 파일을 두 번 바꿈.
- **관찰**: 새 렌더링이 이전 결과 바로 뒤에 구분선, 화면 지우기, 프레임 번호 없이 이어 붙는다. 실제 출력은 `text` 다음 줄에 `two`(다음 프레임의 제목)가 바로 이어졌다.
- **영향**: 에이전트가 로그를 읽거나 사람이 TTY에서 `-P -W`를 쓰면 스크롤백이 쌓이고 최신 프레임이 어디부터인지 알 수 없다. 파일이 지워진 경우의 오류는 stderr 한 줄로 한 번만 나와 구분은 된다.
- **한계**: 사람이 쓰는 감시 화면의 표준 경로는 페이저(`-W`)이므로 영향 범위는 비 TTY 소비자 위주다.

### F4. 드래그 선택 복사가 tmux 기본 설정에서 전달되지 않음 (우선순위 중간)
- **재현(부분)**: tmux 3.8 기본값은 `set-clipboard external`. 이 값에서 애플리케이션이 보낸 OSC 52를 패널에서 내보내면 tmux 버퍼가 비어 있고, `set-clipboard on`으로 바꾸면 버퍼에 들어간다(`list-buffers`로 확인).
- **소스 확인**: tmux 마스터 `input.c`의 `input_osc_52_parse()`는 `set-clipboard`가 2(on)가 아니면 바로 0을 돌려 시퀀스를 버린다.
- **관찰**: dg는 드래그가 끝나면 OSC 52를 쓰고(`links::clipboard_sequence`), 복사 성공을 알리는 메시지가 없다. 코드 주석은 "지원 안 하는 터미널은 무시하므로 실패 상태가 없다"고 가정한다(`links.rs:159-161`).
- **영향**: tmux 기본 설정 사용자는 드래그해도 클립보드가 안 바뀌고, 바뀌었는지 알 방법도 없다. "dg 출력을 AI에게 붙여 넣는" 흐름이 조용히 끊긴다.
- **우회 존재**: `-P` 출력을 `pbcopy` 등으로 파이프하거나 `s` 키로 원문을 보고 터미널 자체 선택을 쓸 수 있다. 다만 마우스 추적(1002)을 켜 두므로 터미널 자체 선택은 보통 Shift 드래그가 필요하다(코드 주석 `pager.rs:138-141`).
- **미확인**: OSC 52가 바깥 터미널(ghostty 등)까지 실제로 전달되는지는 헤드리스 환경이라 관찰하지 못했다.

### F5. 배색 자동판별이 멀티플렉서 안에서 항상 어두운 테마로 떨어짐 (우선순위 중간)
- **코드**: 자동판별은 `COLORFGBG`만 본다(`main.rs:161-167`). 값이 없으면 어두운 테마다.
- **관찰**: ghostty 위 tmux 패널의 환경에 `TERM=tmux-256color`, `COLORTERM=truecolor`, `TERM_PROGRAM=tmux`가 있고 `COLORFGBG`는 없다. 이 세션을 연 ghostty 환경에도 `COLORFGBG`가 비어 있다.
- **영향**: 밝은 배경 터미널 사용자는 `-s light` 또는 `DG_STYLE=light`를 직접 줘야 한다. 어두운 테마의 제목 4~6단계(회색 252, 250, 248)와 인용 글자(246)는 흰 배경에서 대비가 낮을 것으로 보인다(코드 값 기준 추정, 실제 화면은 보지 못함).
- **대안 후보(미검증)**: 터미널에 배경색을 직접 묻는 OSC 11 질의에 tmux가 응답하는 코드가 있고(`input_osc_11`), 테마 알림용 `CSI ? 996 n`과 모드 2031도 있다. dg가 이를 쓰면 의존성 추가 없이 가능한지는 설계 단계 조사 대상이다.
- **참고**: `DG_STYLE`은 `--help`에 나오지 않는다(F6).

### F6. 에이전트용 실행 문맥에서 알 수 없는 기본값 (우선순위 낮음)
- **관찰**: TTY가 없으면 자동으로 인쇄 모드, 색 없음, 폭 80이다. `COLUMNS=50`을 주면 폭이 50으로 바뀌는 것을 확인했다(`COLUMNS=200`은 문단 120 상한 때문에 최대 97칸).
- **관찰 2**: `COLUMNS`, `DG_STYLE`, `DG_DIRECTION`, `DG_ER_NOTATION`, `DG_DEPTH`가 `--help`에 없다. AI가 `dg --help`만 읽으면 폭을 맞추는 방법으로 `-w`만 안다.
- **영향**: 에이전트는 분할 창 폭을 알 수 없으니 기본 80칸으로 렌더링한 결과를 본다. 사람이 보는 창과 폭이 다르면 같은 문서가 다르게 보인다.

### F7. 감시 갱신 후 보던 위치와 펼침 상태의 어긋남 (우선순위 낮음, 소스 읽기 기반)
- **코드**: `rerender()`는 스크롤 맨 위 줄 번호를 그대로 유지하고, 펼침 플래그는 블록 인덱스 기준으로 `resize`만 한다(`pager.rs:247-254`).
- **추정**: AI가 문서 위쪽에 줄이나 다이어그램을 끼워 넣으면 사용자가 보던 내용이 아래로 밀리고, 펼친 블록 표시가 다른 블록으로 옮겨 간다.
- **미확인**: 재현하지 못했다. `dg-watch-mode` 요구사항 3.1은 "맨 위 줄 기준 유지"까지만 보장하므로 모순은 아니다.

## 문제 없음 (재현해서 확인한 것)
- **폭 변경 반영**: tmux 창을 100칸에서 40칸으로 줄이자 약 1초 안에 다시 그려졌다. 이벤트 루프가 폴링 때마다 터미널 크기를 다시 읽는다(`pager.rs:151`).
- **파일 변경 반영**: 40칸 창에서 파일을 바꾸자 1.2초 안에 새 내용으로 갱신됐다.
- **깜빡임 억제**: 페이저가 동기화 갱신(`BeginSynchronizedUpdate`)과 줄 단위 덮어쓰기를 쓰고, 변경이 없으면 다시 그리지 않는다(`pager.rs:653`, `167`). 실제 깜빡임은 눈으로 보지 못했다.
- **줄 폭 초과**: `-w` 30~120에서 최대 줄 폭이 지정 폭을 넘지 않았다(architecture.md 기준 120, 80, 60, 50, 40, 30).
- **시작 오류**: 파일이 없으면 종료 코드 1과 `dg: ...` 메시지가 나온다.

## 측정 한계
- architecture.md 전체의 폭별 대체 개수는 본문 일치로 세려다 오판해서(문서가 원문을 이미 인용함) 버렸다. 대체 경계는 sequence.md 첫 블록의 표지로만 확인했다.
- herdr 패널에서 pager를 띄워 `herdr pane read`로 화면을 읽는 경로는 실행하지 않았다. herdr에는 패널 출력을 읽는 명령이 있어 에이전트가 화면을 볼 수는 있으나, 어떤 신호가 필요한지는 이 조사로 확정하지 못했다.
- 중간 저장 상태(파일을 비운 뒤 쓰는 도구)에서 감시가 빈 문서를 한 번 그리는지는 확인하지 않았다. 폴링 300ms 대비 쓰기 창이 짧아 확률은 낮다고 본다.

## 요구사항으로 넘길 후보와 결정 필요 사항

요구사항 초안의 승인 기준 후보는 아래 순서다. 근거가 약한 항목은 사용자 결정 뒤에 넣는다.

1. F1과 F2: 대체 사실과 사유를 사람과 에이전트가 모두 알 수 있게 한다. 사람용 본문 포맷은 유지한다.
2. F4: 복사가 실제로 전달됐는지, 안 됐을 때 대안이 무엇인지 사용자에게 알린다.
3. F5: 배색 자동판별이 멀티플렉서에서 유효하지 않을 때의 동작을 정한다.
4. F3: 비 TTY 감시 출력의 프레임 구분.
5. F6, F7: 문서화와 재현 확인 후 결정.

**사용자 결정이 필요한 것**
- 에이전트용 신호의 형태: 종료 코드(예: 대체가 있으면 0이 아닌 값), stderr 요약, 전용 옵션 중 무엇을 쓸지. 종료 코드를 바꾸면 기존 스크립트 호환(brief의 하위호환 제약)과 충돌할 수 있어 옵션으로 켜는 쪽이 안전해 보인다.
- 사용자의 실제 환경(herdr 안인지 tmux 안인지, 터미널 배경이 밝은지)과 가장 자주 만나는 마찰이 어느 것인지.
