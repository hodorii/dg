# 버그 수정 - bpmn-pool-lane-rendering-polish

## 정의
BPMN 협업 다이어그램을 가로(LR)와 세로(TB) 모두에서 풀과 레인이 포함 관계로 읽히게 하기 위해, 풀과 레인 테두리, 메시지 흐름 접점, 노드와 경계선의 겹침, 꺾이는 선, 경계 이벤트 선을 바로잡는 결함 수정이다.

## 재현 절차
1. 환경: 수정 전 커밋 `8c84742`, `cargo build --release`, `./target/release/dg -P -s none -w 160 --direction <tb|lr> examples/bpmn.md`. 입력은 두 번째 `bpmn` 코드블록(주문 처리 협업: 블랙박스 풀 `고객`, 레인 `영업`과 `창고`를 가진 풀 `판매사`, 메시지 흐름 `고객` -> `received`, 경계 타이머 `timeout`).
2. 예제 XML에는 원래 어느 레인에도 속하지 않은 노드(`notified`)가 있었다. 레인이 있는 풀의 노드는 모두 레인에 속해야 하므로 사용자가 예제를 고쳤다(`sales` 레인에 추가). 이 항목은 코드 결함이 아니라 아래 재현은 고친 예제 기준이다.
3. 관찰 결과(세로, 발췌):
   ```
   ├──────────────────────────────────┼────────────────────┤   ├─ ─────────┤
   │                     ╎ │          │
   │                     ◎ 시한 초과  │
   │                       «timer»    │
   │                     │            │
   │                      ╭─╯         │        ╭──╯        │
   └──────────────────────◉ 안내 완료─┴────────◉ 출고 완료─┘   └──┼────────┘
                                                                  ╎
   ```
4. 관찰 결과(가로, 발췌):
   ```
   │        │      │                    │ │           │─╮              ╭▶│   «service»    │──▶◉ 안내 완료
   ┌───────────────┬──────┼──────────────────────────────────
   │고객           │      ╎
   │                      ╰╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┼
   │               │
   ```
5. 0층 노드 겹침 재현: 풀 > 레인 > 하위 레인 YAML(`participants: vendor/lanes: sales/lanes: senior/nodes: a: startEvent ...`)을 세로로 렌더링하면 첫 이벤트가 구분선 줄에 그려진다(`├──────○─────┼`), 가로에서는 구분선 칸에 그려진다(`│      ○──▶│`).

## 범위
- **포함**: 레인(풀) 그룹의 테두리와 구분선, 풀 닻으로 가는 메시지 흐름의 배선, 레인 안 노드 배치(경계선과의 간격, 일직선 정렬), 세로 배치의 2줄 이벤트 출구, BPMN 경계 이벤트 연결선의 선 종류.
- **제외**: 경계 이벤트를 호스트 테두리 위에 올려 그리는 것(후속), 레인 밖 노드의 검증 오류화, mermaid `bpmn-beta` 문법, 레인이 없는 그래프(흐름도 등)의 배치.

## 동작

### 1. 현재 동작 (결함)
- 1.1: [노드가 없는 블랙박스 풀] 제목 칸 경계선이 중간에 끊긴다(세로 `├─ ─────────┤`, 가로 `고객` 풀의 제목 칸 오른쪽 세로선이 일부 줄에서 사라짐).
- 1.2: [하위 레인이 없는 풀 또는 레인] 제목 칸이 다른 풀의 가장 깊은 레인 배너까지 차지한다(가로 `│고객           │`처럼 레인 두 단 폭, 세로도 같은 깊이만큼 아래로 내려온 구분선).
- 1.3: [블랙박스 풀에서 나가거나 들어오는 메시지 흐름] 선이 풀 면이 아니라 흐름축 끝(가로는 풀 오른쪽 끝, 세로는 풀 아래쪽)에 붙고, 세로에서는 다이어그램 아래로 빠져나간 점선이 남는다.
- 1.4: [레인 안 첫 층과 마지막 층 노드] 첫 층 노드는 레인 구분선 위에, 마지막 층 노드는 풀 아랫변(가로는 오른쪽 테두리) 위나 바깥에 그려져 경계선을 가린다.
- 1.5: [들어오는 선이 하나뿐인 노드가 레인 오른쪽 끝에 가까움, 세로] 이름 폭 때문에 부모 출구와 같은 칸에 놓이지 못해 선이 지그재그로 꺾인다(`╭─╯`, `╭──╯`).
- 1.6: [이름 아래 둘째 줄이 있는 이벤트, 세로] 나가는 선이 둘째 줄(`«timer»`) 다음 줄부터 시작해 이벤트 글자와 선 사이에 빈 줄이 생긴다.
- 1.7: [경계 이벤트] 호스트에서 경계 이벤트로 가는 연결선이 점선(`╎`, `╌`)이다.

### 2. 기대 동작
- 2.1: [노드가 없는 블랙박스 풀] 제목 칸 경계선이 끊김 없이 이어진다.
- 2.2: [하위 레인이 없는 풀 또는 레인] 제목 칸은 자기 깊이의 배너만 차지하고 그 바로 뒤에 구분선이 있으며, 나머지는 내용 영역이다.
- 2.3: [블랙박스 풀 메시지 흐름] 풀 쪽 끝은 상대를 향한 풀 면(가로는 윗면 또는 아랫면, 세로는 왼쪽 또는 오른쪽 면)의 가운데에 수직으로 닿고, 상대 노드 쪽 끝은 풀을 향한 노드 면에서 나간다. 두 끝 사이는 풀 바로 바깥 통로를 지난다.
- 2.4: [레인 안 첫 층과 마지막 층 노드] 노드(이름 포함)는 레인 구분선과 바깥 테두리에 겹치거나 걸치지 않고 레인 안에 온전히 놓인다. 가로는 양 끝에 한 칸을 더 띄운다.
- 2.5: [1.5와 같은 노드] 레인을 필요한 칸 수만큼 넓혀 부모 출구와 일직선으로 놓인다. 출발 쪽(나가는 선이 하나뿐인 노드)도 같다.
- 2.6: [1.6과 같은 이벤트, 세로] 나가는 선이 이벤트 글자 바로 아래에서 시작해 둘째 줄 옆을 지난다.
- 2.7: [경계 이벤트] 연결선과 이벤트에서 나가는 흐름은 모두 실선이다(차선책. 호스트 테두리 위 배치는 범위 밖).

### 3. 불변 동작 (회귀 방지)
- 3.1: [레인이 없는 그래프] 렌더링 결과가 바이트 단위로 같다(`crossgroup_family_matches_recorded_results_and_stays_fast` 무수정 통과).
- 3.2: [노드끼리 잇는 메시지 흐름과 펼친 Sub-Process 상자의 닻으로 가는 흐름] 기존 층 배선 그대로다.
- 3.3: [같은 풀의 형제 레인] 경계선 하나를 공유하고, 3단 중첩의 아랫변이 한 줄에 모인다.
- 3.4: [방향] `horizontal`은 풀을 위아래로, `vertical`은 좌우로 쌓고, 명령줄 방향 옵션이 문서 값을 덮는다.
- 3.5: [레인 그래프가 폭에 안 들어감] 기존처럼 `None`을 돌려주고 다른 방향이나 원문으로 물러난다.
