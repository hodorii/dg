# Requirements — bpmn-lane-layout

## 정의
BPMN 풀·레인을 문자 그림으로 그려야 하는 후속 스펙(`bpmn-model` 이후)을 위해,
기존 그래프 배치기의 그룹에 "레인" 종류를 더해 그룹 상자가 구성원 범위가 아니라
자기가 속한 범위(다이어그램 전체 또는 부모 레인) 전체를 관통하는 띠로 그려지게
하는 기능이다. 파서 없이 손으로 만든 그래프로만 검증한다.

## Boundary Context
- **In scope**: 그룹에 "레인" 종류 표시, 레인의 띠 범위 강제(최상위면 다이어그램
  전체, 중첩이면 부모 레인 범위), 레인 안 레인 중첩(풀 > 레인 > 하위 레인),
  형제 레인의 테두리 공유 배치와 선언 순서 유지, 레인 제목 배너(TB는 상단 띠,
  LR은 왼쪽 열), 기존 방향(TB/LR) 지정과 폭 초과 폴백 규약 재사용, 레인 없는
  기존 그래프의 렌더링 결과 불변
- **Out of scope**: BPMN 도형·표식 어휘(`bpmn-shapes`), BPMN 의미 계층·검증·
  변환 파이프라인(`bpmn-model`), BPMN XML·`biz-process.md` 파싱(`bpmn-xml`,
  `bizprocess-bpmn`), 코드펜스 언어·CLI 옵션·예제 문서(후속 스펙에서 파서와
  함께 추가), 구성원이 하나도 없는 레인의 표시(기존 빈 그룹과 같이 그려지지
  않음 — 자리표시 노드를 넣을지는 `bpmn-model`이 결정), 레인 자체를 간선의
  끝으로 쓰는 것(그룹 닻), LR 배너의 세로쓰기 제목(가로쓰기만)

## Acceptance Criteria

### 1. 레인 띠의 범위
- 1.1: [최상위 그룹을 레인 종류로 표시 + 구성원 노드가 일부 층에만 있음] →
  [레인 상자가 흐름 방향으로 다이어그램의 첫 층부터 마지막 층까지 전부 관통한다]
- 1.2: [레인 종류가 아닌 그룹(기존 그룹)] → [지금처럼 구성원이 있는 층 범위만
  감싼다 — 동작 변화 없음]
- 1.3: [레인 안에 중첩된 레인] → [자식 레인 상자가 부모 레인의 흐름 방향 범위
  전체를 관통한다]
- 1.4: [같은 부모 아래 형제 레인 둘 이상] → [흐름 방향과 직교하는 방향으로
  나란히 놓인 띠로 그려진다(위→아래면 좌우로, 왼쪽→오른쪽이면 위아래로)]

### 2. 형제·부모 레인의 테두리와 순서
- 2.1: [형제 레인 둘이 이웃함] → [두 레인 사이 경계가 한 줄(칸)이고, 두 줄이
  나란히 그려지지 않는다]
- 2.2: [형제 레인의 경계가 부모 레인 테두리와 만남] → [만나는 칸이 분기
  문자(`┬`·`┴`·`├`·`┤`)로 이어진다]
- 2.3: [부모 레인 안의 자식 레인들] → [첫 자식·마지막 자식의 바깥쪽 테두리와
  흐름 방향 끝 테두리가 부모 레인 테두리와 같은 줄(칸)이다]
- 2.4: [형제 레인을 A, B, C 순서로 선언 + 간선 연결이 다른 순서를 선호함] →
  [A, B, C 선언 순서 그대로 그려진다]
- 2.5: [형제 레인 + 폭 초과로 층 접기 폴백이 일어남] → [레인은 접히지 않고
  나란한 띠를 유지하며, 레인 안의 노드만 접힌다]

### 3. 레인 사이 흐름
- 3.1: [레인 A의 첫 노드에서 레인 B의 노드로 간선 + A 안에 뒤따르는 노드가 더
  있음] → [B의 노드는 A의 첫 노드 바로 다음 층에 놓이고, A의 마지막 노드 뒤로
  밀리지 않는다]
- 3.2: [간선이 레인 경계를 넘음] → [선이 끊김 없이 그려지고 화살촉이 도착
  노드에 붙는다]
- 3.3: [레인 밖 노드(최상위)와 레인이 한 그래프에 섞임] → [레인 밖 노드는 레인
  상자 바깥에 그려지고 패닉이 없다]

### 4. 제목 배너
- 4.1: [위→아래 방향 레인] → [제목이 레인 상단의 전용 줄(노드 내용 위)에
  쓰이고, 테두리 선 위에 겹쳐 쓰이지 않는다]
- 4.2: [왼쪽→오른쪽 방향 레인] → [제목이 레인 왼쪽의 전용 열(노드 내용 왼쪽)에
  가로쓰기로 쓰이고, 테두리 선 위에 겹쳐 쓰이지 않는다]
- 4.3: [중첩 레인] → [자식 레인의 배너가 부모 레인의 배너 다음에 오며 두 제목이
  겹치지 않는다]
- 4.4: [같은 깊이의 형제 레인 제목 길이가 서로 다름] → [모든 형제의 노드 내용이
  흐름 방향으로 같은 위치에서 시작한다]
- 4.5: [위→아래 방향 + 제목이 구성원 노드들보다 넓음] → [레인이 제목 폭만큼
  넓어지고 제목이 잘리지 않는다(기존 그룹 제목과 같은 규약)]
- 4.6: [제목이 빈 문자열인 레인] → [배너 자리는 유지하되 글자는 쓰지 않는다]

### 5. 방향과 폭 초과
- 5.1: [방향 지정 없음] → [기존 기본값(위→아래)으로 레인이 좌우로 나란히
  그려진다]
- 5.2: [왼쪽→오른쪽 지정] → [레인이 위아래로 쌓인 가로 띠로 그려진다]
- 5.3: [지정 폭 초과] → [기존 규약(반대 방향 재시도 → 라벨 축소 → 실패 시
  결과 없음) 그대로 따르며, 재시도 결과도 1~4를 만족한다]

### 6. 회귀·안전
- 6.1: [항상 + 레인 종류 그룹이 하나도 없는 그래프] → [렌더링 결과가 이 기능
  이전과 바이트 단위로 동일하다]
- 6.2: [항상] → [어떤 레인 구성(3단 중첩, 구성원 없는 레인, 레인 밖 노드 혼재,
  레인 사이 되돌아가는 간선)에도 패닉이 없다]
