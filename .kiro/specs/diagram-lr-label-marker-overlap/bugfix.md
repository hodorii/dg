# Bugfix — diagram-lr-label-marker-overlap

## 정의
가로(LR) 방향 그래프형 다이어그램을 읽는 사용자를 위해, (1) 관계 라벨이 두 글자짜리
from측 표식(까치발 등)의 두 번째 글자를 덮어써 지우는 결함과 (2) from측·to측 라벨
(카디널리티·다중성 등)이 표식과 달리 노드 경계에 바로 붙지 않고 빈 칸 하나를 남기던
불일치를 함께 고치는 수정이다.

## 재현 절차
1. 환경: `make install` 후 `~/.local/bin/dg`(release 빌드), 비대화형 출력(`-P -s none`),
   폭 100 이상(줄바꿈 재시도 배제).
2. 입력(까치발 두 글자 표식 + 라벨): `CUSTOMER }o--|| ORDER : places`(zero-or-many가
   CUSTOMER 쪽에 있어 tail 표식이 `CrowZeroMany`, 두 글자: `○`+`>`/`<` 계열).
   명령: `dg -P -s none -d -l mermaid --direction lr -w 100 <파일>`
3. 관찰(수정 전, 글자 손실): `│ CUSTOMER │>places──╫│ ORDER │` — `CrowZeroMany`는
   두 글자(`○`, `>`)여야 하는데 `○`가 사라지고 `>`만 남는다. `places`(관계 라벨)가
   표식의 두 번째 글자 자리를 그대로 덮어썼다.
4. 입력(실제 문서): `examples/architecture.md`의 `classDiagram`(`direction LR`)을
   `dg -P -s none -w 220 examples/architecture.md`로 렌더링.
5. 관찰(수정 전, from측 경계 불일치): 표식 줄은 `├──────────────────────┤♦nodes───`
   처럼 경계에 표식이 바로 붙는데, 바로 위 카디널리티 줄은
   `│        Graph         │ 1` 처럼 경계와 숫자 사이에 빈 칸이 하나 있다(사용자
   지적: "가로 선일 때 … 붙어야").
6. 관찰(수정 전, to측 경계 불일치): 같은 문서에서 `Node`측 다중성 `*`도
   `│  * │ +String id` 처럼 `Node` 경계 앞에 빈 칸이 남는다 — from측(`1`)과 같은
   문제가 반대쪽(`*`)에도 있다(사용자 지적: "1 반대편인 * 도 마찬가지 아니겠나?").

## Boundary Context
- **In scope**: LR 방향에서 from측·to측 표식·라벨(`label`, `tail_label`,
  `head_label`)의 가로 위치 — 표식이 2글자 이상일 때 라벨이 표식 글자를 덮어쓰는
  문제, tail_label·head_label이 표식이 실제로 차지하는 칸 수와 무관하게 항상 노드
  경계에 바로 붙어야 하는 문제(둘 다 표식과 다른 줄에 그려지므로 표식 글자 수를
  신경 쓸 필요가 없다)
- **Out of scope**: 관계 라벨(`label`)과 표식이 같은 줄에서 붙어 있는 배치 자체를
  다른 줄로 재구성하는 것(검토했으나 기각 — design.md 참고), TB(세로) 방향,
  `diagram-lr-tail-label-position`에서 이미 고친 "레이어 공용 위치" 문제 자체

## Behaviors

### 1. 현재 동작 (결함)
- 1.1: [LR 방향에서 from측 표식이 두 글자(예: `CrowZeroMany`)이고 관계 라벨이 있을 때]
  → [라벨이 표식의 두 번째 글자를 덮어써 그 글자가 화면에서 사라진다]
- 1.2: [LR 방향에서 tail_label(카디널리티 등)이 있을 때] → [표식 줄은 경계에 바로
  붙는데 tail_label 줄만 경계와 글자 사이에 빈 칸이 하나 남아 붙는 정도가 서로 달라
  보인다]
- 1.3: [LR 방향에서 head_label(다중성 등)이 있을 때] → [tail_label과 같은 이유로
  to측 경계와 글자 사이에도 빈 칸이 하나 남는다]

### 2. 기대 동작
- 2.1: [LR 방향에서 from측 표식이 몇 글자든] → [표식 글자가 모두 그대로 보이고, 라벨이
  그 글자를 덮어쓰지 않는다]
- 2.2: [LR 방향에서 tail_label이 있을 때] → [표식 글자 수와 무관하게 노드 경계 바로
  다음 칸에 붙어, 표식 줄이 경계에 붙는 것과 같은 간격으로 보인다]
- 2.3: [LR 방향에서 head_label이 있을 때] → [표식 글자 수와 무관하게 to측 노드 경계
  바로 앞 칸에 붙는다 — from측(2.2)과 대칭이다]

### 3. 불변 동작 (회귀 방지)
- 3.1: [`diagram-lr-tail-label-position`에서 고친 동작 — 같은 레이어에 폭이 다른
  개체가 있어도 from측 라벨이 자기 노드 옆에 붙는 것] → [그대로 유지된다]
- 3.2: [관계 라벨(`label`)이 표식 바로 다음 칸에서 시작하는 배치(표식·라벨이 같은
  줄에 붙어 보이는 것)] → [줄 구성 자체는 바꾸지 않았으므로 그대로 유지된다]
- 3.3: [TB(세로) 방향의 라벨 위치, 표식 자체의 글자·방향] → [지금처럼 유지된다]
