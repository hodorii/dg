# Requirements — gitgraph-branch-distinction

## 정의
여러 브랜치가 섞인 gitGraph를 읽는 사용자를 위해, 색상과 선패턴을 트랙(브랜치)마다 이중으로
자동 배정해 라벨 텍스트 없이도 브랜치를 시각적으로 구분 가능하게 하는 기능이다.

## Boundary Context
- **In scope**: 가로 모드·세로 모드(TB/BT) 모두에서 트랙별 색+선패턴 자동 순환 배정, `--style none`에서
  선패턴만으로의 식별성, 분기·병합 연결선과 병합 커밋 점의 색/패턴 귀속 규칙, 트랙 수가 배정 가능한
  조합 수를 넘을 때의 순환 재사용
- **Out of scope**: 사용자가 색·선패턴을 직접 지정하는 옵션, 가로/세로 배치 로직 자체 변경
  (`gitgraph-vertical-mode` 소관), 색맹 접근성 감사(선패턴을 통한 비색상 식별로 대응하며 별도 검증은
  다루지 않음), PlantUML gitGraph(존재하지 않음)

## Acceptance Criteria

### 1. 브랜치별 색 배정
- 1.1: [트랙(브랜치) 2개 이상] → 트랙마다 서로 다른 색이 트랙 선·커밋 점·브랜치 이름 라벨에
  일관되게 적용됨
- 1.2: [트랙 개수가 사용 가능한 색 종류 수를 초과] → 색이 앞에서부터 순환 재사용되어 패닉 없이
  렌더링됨
- 1.3: [세로 모드(TB/BT)] → 가로 모드와 동일한 규칙으로 트랙별 색이 적용됨

### 2. 브랜치별 선패턴 배정
- 2.1: [트랙 2개 이상] → 색과 별개로 선패턴(실선/파선/굵은선 등)이 트랙마다 순환 배정되어, 인접한
  두 트랙이 같은 패턴이어도 색으로, 같은 색이어도 패턴으로 구분 가능함
- 2.2: [단일 브랜치(트랙 1개, 예: `main`만)] → 기존과 동일하게 단일 실선 스타일로 렌더링됨(회귀 없음)

### 3. `--style none`에서의 식별성
- 3.1: [`--style none`, 트랙 2개 이상] → 색상 출력 없이도 선패턴만으로 트랙이 서로 구분됨
- 3.2: [`--style none`, 트랙 개수가 선패턴 종류 수를 초과] → 선패턴이 순환 재사용되어 패닉 없이
  렌더링됨

### 4. 분기·병합 연결선
- 4.1: [`branch`로 새 트랙이 갈라짐] → 분기 연결선이 새로 생기는 트랙의 색·선패턴을 따름
- 4.2: [`merge`로 두 트랙이 합쳐짐] → 병합 연결선이 합류해 들어오는(source) 트랙의 색·선패턴을
  따르고, 병합 커밋 점은 대상(target) 트랙의 색을 따름

### 5. 회귀
- 5.1: [트랙 1개인 기존 gitGraph 입력] → 이번 변경 전과 동일한 렌더링 결과(글자·구성)가 유지됨
- 5.2: [항상] → 어떤 입력에도 비정상 종료(패닉)하지 않음
