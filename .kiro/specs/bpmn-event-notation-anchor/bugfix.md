# Bugfix — bpmn-event-notation-anchor

## 정의
BPMN 그림에서 흐름이 이벤트 표기(원 글자)에 닿는지 한눈에 확인하려는 사용자를 위해, 이벤트 이름의 길이에
따라 원 글자가 흐름선에서 벗어나는 결함과 종료 이벤트 글자가 상태도의 끝점 관례(`◉`)와 다른 결함을 고치는
수정이다. 사용자 지적(2026-09-27, `bpmn-event-shape-notation` 출고 직후): "완료: ◉가 맞을 듯",
"이벤트가 텍스트가 아니라 노테이션으로 취급해야 하므로, 위치가 선에서 벗어나지 않게 해야 함. 텍스트 추가로
위치가 바뀌는 상황이 보임."

## 재현 절차
1. 환경: 커밋 `c98f3d9`(bpmn-event-shape-notation 구현). `layout::graph::tests`에 손으로 만든 `Graph`를
   `render(&g, &Theme::none(), 100)`으로 그리는 임시 테스트(실행 뒤 제거)와
   `cargo run -- -P --width 100 examples/bpmn.md`.
2. 입력(위→아래, 기본 방향): `Round "Task"` → `Event(End)` 이름 `""` / `"Done"` / `"주문 취소"` 세 그래프.
3. 관찰(위→아래) — 화살촉 `▼`와 원 글자 `●`의 열:
   ```
   ╭──────╮        ╭──────╮         ╭──────╮
   │ Task │        │ Task │         │ Task │
   ╰──────╯        ╰──────╯         ╰──────╯
       │               │                │
       ▼               ▼                ▼
       ●            ● Done         ● 주문 취소
   ```
   이름 없음: `▼`·`●` 모두 4열(선 위). `"Done"`: `▼` 4열, `●` 1열(3칸 왼쪽). `"주문 취소"`: `▼` 5열,
   `●` 0열(5칸 왼쪽). 화살촉이 이름 글자 위에 떨어지고, 이름이 길수록 원 글자가 선에서 멀어진다.
4. 입력(위→아래): `Event(Start)` 이름 `""`/`"Go"`/`"주문 접수 «message»"` → `Round "Task"`.
   관찰: 흐름선이 `○`에서 나오지 않고 이름 위 열에서 나온다 — `"Go"`는 `○` 2열·선 4열,
   `"주문 접수 «message»"`는 `○` 0열·선 10열.
5. 입력(위→아래): `Round "A"`·`Round "B"` → `Event(End) "Done"`(들어오는 간선 둘).
   관찰: `▼` 8열·10열, `●` 6열 — 두 화살촉 모두 이름 `Done` 위에 떨어지고 원 글자에는 어느 것도 닿지 않는다.
   ```
     │       │
     ╰─────╮ │
           ▼ ▼
         ● Done
   ```
6. 입력(왼쪽→오른쪽): `Round "Task"` → `Event(End)` 본문 `["Done"]` / `["Done", "«timer»"]` /
   `["one", "two", "three"]`.
   관찰: 한 줄·두 줄은 `▶` 바로 오른쪽이 `●`(정상). 세 줄은 `●`가 0번 줄, `▶`가 1번 줄 — 원 글자가 선보다 한 줄
   위에 있고 화살촉은 둘째 줄 `two` 앞에 닿는다.
   ```
   ╭──────╮   ● one
   │ Task │──▶  two
   ╰──────╯     three
   ```
7. 입력(왼쪽→오른쪽): `Round "A"`·`Round "B"` → `Event(End)` 본문 세 줄(들어오는 간선 둘).
   관찰: `●`가 3번 줄, `▶`는 3번 줄과 5번 줄 — 하나만 우연히 원 글자에 닿고 다른 하나는 `three` 앞에 닿는다.
8. 관찰(실물, `examples/bpmn.md` 둘째 협업 그림): `○ «message»`의 아래 선이 `○`에서 5칸 오른쪽에서 내려가고,
   `◎ 시한 초과`/`«timer»`의 선은 `◎`에서 5칸 오른쪽, `▼`→`● 주문 취소`는 `▼` 7열·`●` 2열,
   `▼`→`● 출고 완료`는 `▼` 46열·`●` 41열. 첫 프로세스 그림(왼쪽→오른쪽, 한 줄 본문)은 `──▶● 완료`로 정상.
9. 관찰(글자): 종료 이벤트 글자는 `●`(U+25CF). 같은 파일의 상태도 끝점은 `◉`(U+25C9), 시작점이 `●` —
   "채운 원 = 시작, 겹원 = 끝" 관례가 이미 있는데 BPMN 종료가 시작점과 같은 글자를 쓴다.

## Boundary Context
- **In scope**: `Shape::Event` 노드에 드나드는 간선의 접점 위치와 노드 정렬 기준(위→아래·왼쪽→오른쪽 모두);
  `Shape::Event` 그리기의 원 글자 위치; 종료 이벤트 글자 `●` → `◉`; 이 출력에 의존하는 기존 테스트 기대값
  (`layout::shape`·`layout::graph`·`bpmn::mod`); `●`를 종료 글자로 적은 이전 스펙 문서의 한 줄 포인터
- **Out of scope**: 다른 모양(`Round`·`Subprocess`·`Rect`·`Diamond`·`Circle`·`Plain`·`Interface`·`Actor` 등)의
  접점·가운데 정렬; 상태도 `Shape::Start`/`Shape::End`(글자 선례로만 참조); `bpmn::model`·`validate`·`lower`·
  `parse_xml`·`vocabulary`의 의미 논리(`ElementKind::Event → Shape::Event(position)` 매핑 그대로); 간선 라벨
  위치·통로 배정·교차 처리 규칙 일반; 이벤트 자기 간선; 시작 `○`·중간 `◎` 글자; 새 예제 파일

## Behaviors

### 1. 현재 동작 (결함)
- 1.1: [위→아래, 이름 있는 종료 이벤트로 들어오는 간선] → [`▼`가 "원 글자 + 이름" 덩어리의 가운데 열(이름 위)에
  오고, `●`는 그보다 왼쪽 — 이름이 길수록 멀어진다(`"Done"` 3칸, `"주문 취소"` 5칸)]
- 1.2: [위→아래, 이름 있는 시작 이벤트에서 나가는 간선] → [선이 `○`가 아니라 이름 위 열에서 시작한다]
- 1.3: [위→아래, 이벤트로 들어오는 간선 둘] → [화살촉 둘이 이름 위에 벌려 놓이고 어느 것도 원 글자에 닿지
  않는다]
- 1.4: [왼쪽→오른쪽, 본문 세 줄 이상인 이벤트] → [`▶`가 가운데 줄(둘째 줄 앞)에 닿고 원 글자는 그 위 줄에 있다;
  들어오는 간선이 둘이면 화살촉이 위아래로 벌려져 원 글자 줄과 어긋난다]
- 1.5: [이름 없는 이벤트 → 같은 이벤트에 이름 추가] → [원 글자가 선 위에서 이름 폭의 절반만큼 옆으로 밀려난다
  (사용자 관찰 "텍스트 추가로 위치가 바뀜")]
- 1.6: [종료 이벤트] → [`●`(U+25CF) — 상태도 시작점과 같은 글자, 상태도 끝점 `◉`와 다르다]

### 2. 기대 동작
- 2.1: [위→아래, 이름 있는 종료 이벤트로 들어오는 간선] → [`▼`가 원 글자 바로 위 칸(같은 열)에 온다 — 이름
  길이와 무관]
- 2.2: [위→아래, 이름 있는 시작 이벤트에서 나가는 간선] → [선이 `○` 바로 아래 칸(같은 열)에서 시작한다]
- 2.3: [위→아래, 이벤트로 들어오는 간선 둘] → [두 선이 원 글자 바로 위 한 칸으로 모여 닿는다(상태도 `●`/`◉`에
  간선 여럿이 닿을 때와 같은 방식)]
- 2.4: [왼쪽→오른쪽, 본문 세 줄 이상인 이벤트] → [`▶`가 원 글자 바로 왼쪽 칸(같은 줄)에 온다; 들어오는 간선이
  둘이어도 모두 그 칸으로 모인다]
- 2.5: [이름 없는 이벤트 → 같은 이벤트에 이름 추가] → [원 글자는 그대로 선 위에 있고 이름만 오른쪽으로 덧붙는다
  — 원 글자의 열(위→아래)·줄(왼쪽→오른쪽)이 이름 유무·길이·배치기가 노드에 준 여분 폭·높이와 무관하게 노드
  원점에 고정된다]
- 2.6: [종료 이벤트] → [`◉`(U+25C9) — 상태도 끝점과 같은 "겹원 = 끝" 글자; `○ Go`·`◎ Go`·`◉ Go`]

### 3. 불변 동작 (회귀 방지)
- 3.1: [`Rect`·`Round`·`Stadium`·`Cylinder`·`Diamond`·`Hexagon`·`Subroutine`·`Circle`·`Note`·`Plain`·`Actor`·
  `Interface`·`Subprocess`·상태도 `Start`/`End`·그룹 닻] → [접점 위치·정렬·출력이 글자 단위로 이전과 같다(기존
  도형·배치·상태도 테스트 무수정 통과)]
- 3.2: [`examples/*.md` 중 `bpmn.md` 외 전부] → [`dg -P --width 100` 출력 바이트 동일]
- 3.3: [왼쪽→오른쪽, 본문 한 줄·두 줄 이벤트] → [`▶` 바로 오른쪽이 원 글자 — 지금과 같다]
- 3.4: [이벤트 그리기] → [테두리 글자 없음; 원 글자 강조색, 이름 굵게, `«…»` 둘째 줄 흐림·기울임, 이름 없으면
  1×1, 둘째 줄은 이름 시작 열(bpmn-event-shape-notation 2.1~2.5)]
- 3.5: [`lower()`의 이벤트 요소] → [`Shape::Event(position)`, 본문 `[이름]`/`[이름, "«trigger»"]`/`[]` 그대로]
- 3.6: [이벤트·게이트웨이에 쓰는 글자] → [`○`·`◎`·`◉`·`×`·`+`·`*`·`╱` — 기본 CJK 모노 폰트 커버리지 실측
  (`bpmn-shapes/research.md` "글자 커버리지 실측", U+25C9 2/2) 안; `●`는 이벤트 글자 목록에서 빠진다]
- 3.7: [주문 처리 협업(`bpmn::tests` 손 모델·bpmn.io fixture)와 손 그래프(`layout::graph::tests`), 이름 없는
  이벤트·한 글자·세 줄 본문·레인·양방향·빗금 조합] → [폭 100 안에서 패닉 없이 렌더링되고 `○`·`◉`·`◎`·`«user»`·
  `«service»`·`«message»`·`«error»`·`× 재고 있음?`·`╱`·`╌`가 모두 있다(`●` 대신 `◉`)]
- 3.8: [배치기가 `min_width`로 늘린 서브프로세스] → [`[+]`가 늘어난 아래 테두리 가운데 — 다른 모양의 가운데 정렬
  규칙은 그대로]
