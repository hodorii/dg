# Bugfix — diagram-crow-foot-orientation

## 정의
ER 다이어그램의 "many" 까치발(crow's foot) 표식이 뾰족한 끝을 개체 쪽에 붙이고 벌어진 끝을
선 쪽에 두어 방향이 뒤집혀 있던 결함을 고치는 수정이다.

## 재현 절차
1. 환경: `dg` 릴리스 빌드(`cargo build --release`), `./target/release/dg --print --diagram
   --lang mermaid <파일>`로 렌더링 확인.
2. 입력 A (세로 방향, "many" 쪽 개체가 아래):
   ```
   erDiagram
       A ||--o{ B : "rel"
   ```
3. 관찰 결과 A:
   ```
     ╪
     │ rel
     ○
     ∨
   ┌───┐
   │ B │
   └───┘
   ```
   `B` 바로 위에 `∨`(뾰족한 끝이 아래로 `B`를 향함)가 놓인다 — 까치발의 관례는 정반대다:
   벌어진(넓은) 끝이 "many" 쪽 개체에 닿고, 뾰족한 끝은 "one" 표식(`╪`) 쪽 선을 향해야 한다.
4. 입력 B (세로 방향, "many" 쪽 개체가 위): `B o{--|| A : "rel"` → `B` 바로 아래에 `∧`(역시
   뾰족한 끝이 `B`를 향함)가 놓여 같은 방향으로 뒤집혀 있다.
5. 입력 C (가로 방향, `--direction lr`): `A ||--o{ B` → `B`(오른쪽 개체) 바로 왼쪽에 `>`
   (뾰족한 끝이 오른쪽 `B`를 향함)가 놓인다 — 마찬가지로 뒤집혀 있다.
6. 대조: `one`(`╪`/`╫`) 표식과 `○`(zero) 표식은 방향성이 없는 글자라 이 결함과 무관하고
   정상이다. 화살표류 표식(`Marker::Arrow`/`Triangle`/`OpenArrow` — 관례상 뾰족한 끝이
   노드를 향하는 게 맞음)도 이 결함과 무관하다.

## Boundary Context
- **In scope**: `src/diagram/layout/graph.rs`의 `marker_glyphs()` 함수 중 `Marker::CrowMany`/
  `Marker::CrowZeroMany`가 쓰는 `many` 글자 선택(방향별 `∧`/`∨`/`<`/`>` 매핑)만.
- **Out of scope**: `one`(`╪`/`╫`)·`○` 표식 자체, `Marker::OpenArrow`(진짜 화살표 용도로
  같은 글자를 재사용하는 다른 마커 — 방향 관례가 정반대라 건드리면 안 됨), ER 카디널리티
  문자열→표식 매핑(`crow_marker()`, `ir.rs`), 다른 다이어그램 타입의 화살표 표식.

## Behaviors

### 1. 현재 동작 (결함)
- 1.1: 세로(top-down) 방향에서 "many" 개체가 아래(`at_top=false`)에 있으면 → 그 개체
  바로 위 글자가 `∨`(뾰족한 끝이 개체를 향함)다.
- 1.2: 세로 방향에서 "many" 개체가 위(`at_top=true`)에 있으면 → 그 개체 바로 아래 글자가
  `∧`(뾰족한 끝이 개체를 향함)다.
- 1.3: 가로(left-right) 방향에서 "many" 개체가 오른쪽(`at_top=false`)에 있으면 → 그 개체
  바로 왼쪽 글자가 `>`(뾰족한 끝이 개체를 향함)다.

### 2. 기대 동작
- 2.1: 1.1과 같은 입력에서 → 글자가 `∧`(벌어진 끝이 아래 개체를 향하고, 뾰족한 끝이 위쪽
  선을 향함)여야 한다.
- 2.2: 1.2와 같은 입력에서 → 글자가 `∨`(벌어진 끝이 위 개체를 향함)여야 한다.
- 2.3: 1.3과 같은 입력에서 → 글자가 `<`(벌어진 끝이 오른쪽 개체를 향함)여야 한다.

### 3. 불변 동작 (회귀 방지)
- 3.1: `one`(정확히 1) 카디널리티 표식(`╪`/`╫`)은 방향과 무관하게 그대로 한 글자만
  찍힌다(기존 회귀 테스트 `crow_one_marker_is_a_single_glyph_not_doubled` 유지).
- 3.2: `Marker::Arrow`/`Marker::Triangle`/단독으로 쓰이는 `Marker::OpenArrow`(까치발이
  아닌 진짜 화살표 용도)의 방향은 이번 수정으로 달라지지 않는다 — 뾰족한 끝이 노드를
  향하는 기존 관례 그대로.
- 3.3: `○`(zero) 표식과 라벨·선 배치는 이번 수정으로 달라지지 않는다.
