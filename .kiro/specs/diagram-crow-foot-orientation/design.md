# Design — diagram-crow-foot-orientation

## 정의
ER "many" 까치발 표식의 방향(벌어진 끝 vs 뾰족한 끝)이 뒤집힌 결함을 고친다.

## 원인 (Root Cause)
`src/diagram/layout/graph.rs`의 `marker_glyphs()`가 `many` 글자를 고를 때
`Marker::OpenArrow`(실제 화살표 용도 마커)와 **같은 인덱스 배열**
`['∧', '∨', '<', '>']`을 그대로 재사용한다. 화살표는 "뾰족한 끝이 노드에 닿는" 관례가
맞지만(`Marker::Arrow`의 `▲▼◀▶`와 같은 방향), 까치발("many")은 정반대로 "벌어진 끝이
노드에 닿고 뾰족한 끝이 선(반대쪽 카디널리티 표식) 쪽을 향하는" 관례다. 코드 주석은 이
재사용을 "폰트 폴백 성능 문제로 같은 글자 네 개를 그대로 빌려 쓴다"는 이유로만 설명했고,
방향(어느 인덱스에 어느 글자를 배정할지)까지 화살표와 동일하게 가져오면서 까치발 고유의
반대 관례를 반영하지 못했다.

## 수정 방식
글자 네 개(`∧`/`∨`/`<`/`>`)는 그대로 재사용하되(폰트 폴백 회피라는 원래 이유는 유효),
`many` 전용 인덱스 매핑만 top/bottom, left/right를 서로 맞바꿔(`['∨', '∧', '>', '<']`)
벌어진 끝이 노드 쪽을 향하도록 고친다. `OpenArrow` 자신의 글자 배열(`['∧', '∨', '<',
'>']`)은 건드리지 않는다 — 그건 진짜 화살표라 방향이 이미 맞다.
- **대안 비교**: 까치발 전용 새 글자(예: 진짜 세 갈래 갈래꼴 유니코드)를 쓰는 방법도
  검토했으나, 기존 코드 주석이 이미 기록한 "CJK 모노스페이스 폰트 커버리지 밖이라
  스크롤이 느려짐" 문제를 다시 불러올 위험이 있어 기각 — 기존 네 글자 재사용 + 인덱스만
  바꾸는 쪽이 그 회귀를 안 만든다.

## 검증 속성
- (a) 결함 재현: 세로(top/bottom)·가로(left/right) 각각 "many" 쪽 표식 글자를 확인하는
  테스트를 수정 전 코드에 대면 **실패**함(1.1~1.3 — 뾰족한 끝이 개체 쪽)을 확인.
- (b) 기대 동작: 같은 테스트가 수정 후 통과(2.1~2.3 — 벌어진 끝이 개체 쪽).
- (c) 불변 동작: 기존 `crow_one_marker_is_a_single_glyph_not_doubled` 및 화살표류
  방향을 확인하는 기존 테스트가 수정 후에도 그대로 통과(3.1~3.3).

## 영향 범위
- `src/diagram/layout/graph.rs`: `marker_glyphs()`의 `many` 지역 변수 한 줄, 테스트 추가.
- 다른 파일 없음 — mermaid/plantuml 파서는 `Marker::CrowMany`/`CrowZeroMany`를 만들어
  넘기기만 하고 글자 선택 자체는 관여하지 않아 영향 없음.
