# 요구사항 정의서 - bpmn-flow-kind-notation

## 정의
BPMN 다이어그램을 터미널에서 읽는 사용자가 흐름 종류를 선만 보고 구분하도록, 흐름 종류를 양 끝 대상으로 정하고 종류마다 다른 선과 표식을 그리는 흐름 표기 기능이다.

## 범위
- **포함**: BPMN 흐름 표기(1), YAML 흐름 종류 자동 선택(2), 모든 다이어그램의 가로 배치에서 글자 없는 상자 노드의 선 분리(3).
- **제외**: XML과 bizprocess의 흐름 종류 판정, YAML 흐름 문법 자체, 범례, mermaid와 PlantUML의 선 무늬와 표식, 경계 이벤트를 호스트 테두리에 올리는 배치.
- **인접 기대**: 풀 면 중앙 접점과 풀, 레인 테두리는 `bpmn-pool-lane-rendering-polish` 그대로.

## 요구사항

### 1. 흐름 종류별 선과 표식
| 흐름 | 선 | 출발 쪽 | 도착 쪽 |
|---|---|---|---|
| 시퀀스 | `─` `│` | 없음 (기본 흐름은 `╱`) | 채운 화살촉 `▶` |
| 메시지 | `╌` `╎` | `○` | 빈 삼각형 `▷` |
| 데이터 연결 | `┈` `┊` | 없음 | 열린 화살촉 `>` |
| 연결 | `┈` `┊` | 없음 | 없음 |

- 1.1: [항상] 모든 흐름(블랙박스 풀 면으로 드나드는 메시지 포함)이 표대로 그려지고, 표식은 가로, 세로 배치에서 흐름 방향을 가리킨다.
- 1.2: [네 종류가 한 다이어그램에 있음] 꺾임, 교차, 표식을 뺀 곧은 구간만으로 시퀀스, 메시지, 데이터 계열 세 갈래가 구분된다.

### 2. YAML 흐름 종류 자동 선택
| 순서 | 끝 조건 | 종류 |
|---|---|---|
| 1 | 한쪽이 주석 | 연결 |
| 2 | 한쪽이 데이터 객체나 데이터 저장소 | 데이터 연결 |
| 3 | 두 끝의 풀이 다르거나 한쪽이 풀 자체 | 메시지 |
| 4 | 그 밖 | 시퀀스 |

- 2.1: [YAML 흐름] `-->`, `-.->`, `-.-` 중 무엇으로 써도 종류는 표로 정해진다. 그 밖의 화살표 표기는 지금처럼 원문 코드블록으로 물러난다.
- 2.2: [정해진 종류가 기존 흐름 규칙을 어김] 지금처럼 원문 코드블록으로 물러난다.

### 3. 글자 없는 상자 노드의 선 분리
글자 없는 상자 노드: 테두리로 둘러싼 도형이면서 안쪽 글자 줄이 없어 위아래 테두리 두 줄로만 그려지는 노드(예: mermaid `A[" "]`, 이름 없는 BPMN `task`).

- 3.1: [가로 배치 + 글자 없는 상자 노드 + 같은 쪽으로 드나드는 흐름 둘 이상] 흐름마다 다른 줄로 드나든다. 점 모양 노드(상태도 시작과 끝, PlantUML 인터페이스, BPMN 이벤트)는 지금처럼 한 점으로 모인다.

### 4. 기존 동작 유지
- 4.1: [항상] 1~3에 해당하지 않는 렌더링 결과는 이 기능 전과 바이트 단위로 같다. 예외는 예전에 렌더링되던 YAML 흐름의 종류가 2번 표에 따라 바뀌는 경우뿐이다(`-.-`가 연결이 아닌 종류로, 한쪽 끝이 주석인 `-.->`가 연결로).
- 4.2: [항상] 선과 표식 글자는 모두 Noto Sans Mono CJK 커버리지 안이다.
