# 설계서 - bpmn-pool-message-layout

## 정의
풀 사이 메시지를 별도 후처리("풀 간선")가 아니라 보통 선으로 다루어, steering `diagram-architecture.md`의 규칙 R1, R3~R8, R10~R12′, R15~R18을 BPMN에 처음 켜는 증분 I0로 버그픽스 1.1~1.7을 고치는 설계다. R2·R9·R13·R14는 I0에서 legacy 그대로이고(R9 경계 관계는 I2), 근거·검토·측정·로드맵은 `research.md`.

## 원인
- 1.1: 최상위 풀 순서가 노드 등록 순서로만 정해지고 메시지 방향을 보지 않는다(`build_blocks`). — 3.1에서 고침(`lane_precedence`).
- 1.2~1.7의 공통 뿌리: v0.4.0은 풀 끝 메시지를 층 배치에서 빼고(`make_segments`의 `is_pool_edge`) 배치 뒤에 "노드 가운데 행에서 교차축으로 나가 풀 사이 세로 통로로"라는 고정 모양을 준다(`pool_edge_end`). 이 모양은 노드 행을 가로지르므로 같은 풀의 다른 노드·화살촉을 지나고(1.5), 통로 줄을 면마다 따로 세며(1.2), 지나는 다리를 다른 경로와 견주지 않고(1.3), 노드 쪽 끝을 노드마다 한 칸에 두고(1.4), 이름표 자리를 풀 테두리와 견주지 않으며(1.6), 통로 줄에 이름표 칸을 예약하지 않아 자리가 없으면 이름표를 버린다(1.7).
- 3.2~3.7 구현은 이 고정 모양을 유지한 채 사후 탐색(탐욕 다리 옮기기, 우회, 칸 끼우고 되돌리기, 두 번 그려 비교)으로 결과를 고쳤다. 그 결과 결함이 남고(속성 테스트 잔여 6갈래) 메시지가 많은 문서에서 0.4.0 대비 1.3~4배 느려졌으며(원문으로 떨어지는 문서 12.8배), 비용의 60%가 그 탐색이었다(`research.md` §8.1). 남은 비용의 대부분은 legacy의 반복 단계(`improve_by_swaps` 90%, 폭 사다리의 재배치)다.

## 수정 방식
- 3.2~3.7 커밋 6개를 되돌린다(`cf50ba2 → a4b8a4f → 2a388e2 → 66755f0 → f977917 → d92a51d`, 시험상 충돌 없음). 스펙 문서는 되돌리지 않는다. 3.1, 재현 테스트 A~F, 속성 테스트 틀은 유지하고, 되돌리며 지워지는 회귀 사례(입력 B2, G, 예제 주석 우회, 이름표 넓힘 등)는 재현 테스트로 옮긴다.
- 메시지는 보통 선이다. 풀 끝은 선마다 `Segment { gap, container_end }`로 표현하고 `is_pool_edge` 후처리를 지운다(R4·R5, 닻 노드는 빈 레인 자리표시 1×1로만). 메시지의 가로 구간은 노드 없는 간격 줄에만 놓이고(R4), 노드 포트에서 L자로 나가 풀 테두리 칸에서 끝난다(R5).
- 끝 칸: 모든 객체에 접점 규칙 하나(R3), 점 모양 이벤트는 접점 막대(PortBar), 간격 안 접점 열 유일성은 아래 끼움으로(R3′).
- 줄: 같은 간격의 모든 선(시퀀스·메시지)을 교차 최소화 선후 규칙 + 위상 순서로 트랙 배정(R6).
- 이름표: 예약된 칸에만, 덮어 쓰지 않음(R8). 넓힘은 전 높이 열 끼움 하나(R12′).
- 순서·곧게 펴기: 한 번 훑기 무게중심(R1)과 왕복 1회 곧게 펴기(R17). BPMN 경로에서 `improve_by_swaps`, `reorder` 4회, `straighten` 2회, `resolve_port_swaps` 8회를 쓰지 않는다.
- 폭: 고정 시도 목록(선호 방향 → 반대 방향 → TB 행 접기 계산 → 계산한 이름 접기 폭)과 시도마다 결정 한 번(R10·R18). BPMN 경로에서 캡 사다리·`MAX_FOLDS`·`FOLD_PATIENCE`·`FOLD_SEGMENT_LIMIT`를 쓰지 않는다.
- 켜는 경계: `PlacementPolicy`(그래프에 CrossBand 컨테이너가 있으면 규칙 경로). 비 BPMN은 legacy 경로로 0.4.0과 바이트 동일(3.4). 양보 목록과 제거 시점은 steering 호환 경계 표.
- 구현 전 스파이크(tasks 3.9)로 규칙 비용과 3.6 달성 가능성을 확인하고, 미달이면 구현 전에 설계로 돌아온다.
- 기각: 3.2~3.7 방식 유지와 탐색 개선(구조적으로 무결함 보장 불가, 성능 원칙 위반); 대안 B(면 통로 모양 유지, 탐색만 규칙화 — 노드 관통을 규칙으로 막을 수 없음); 대안 C(격자 최단 경로 — 막힘 시 재시도 필요, 10~100배 비용); G5·G6을 I4로 미루기(BPMN 경로에 반복 상한이 남아 3.6 구조 목표 위반, 2026-10-08 사용자 결정으로 I0에 포함).

## 검증 속성
- (a) 재현: 입력 A~F, H, I와 되돌리며 옮긴 사례의 테스트가 수정 전에 실패한다(1.1~1.7).
- (b) 기대: 같은 테스트가 수정 후 통과하고, 속성 테스트(블랙박스·일반 풀, 노드–노드 메시지와 점 모양 다중 끝 포함, TB·LR, 폭 80·120)에서 메시지마다 `○`와 빈 삼각형이 따로 보이고, 선끼리 같은 칸을 같은 방향으로 쓰지 않고, 다른 노드·화살촉을 지나지 않고, 이름표가 모두 그려지고 아무것도 덮지 않는다 — 잔여 0을 목표로 하고 남으면 결함 단위 갈래와 정확한 수를 기록(2.1~2.7).
- (c) 불변: 3.1은 불변 속성 테스트 2.1(개정: 풀·레인 순서와 흐름 표기를 0.4.0과 비교), 3.3·3.5는 기존 테스트, 3.4는 `examples/*.md`·비 BPMN 무작위 문서의 바이트 비교, 3.6은 bugfix 3.6의 측정 방법과 표.
