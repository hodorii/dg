## 0. 요약

- dg의 모든 다이어그램을 **객체·선·세 관계(선·포함·경계)** 모델과 **중첩 띠 격자**로 설명하고, 레이어드 가족에 규칙 R1~R16을 적용한다. 다른 가족(시퀀스·명시 격자·트랙·차트)은 모델을 공유하되 배치 규칙은 가족별이다(§6).
- v3의 변경: R6은 **교차 최소화 선후 규칙 + 위상 순서**(모든 제약 soft, 순환은 시작 좌표로 끊음, 비용 O(k log k + P))로 — 좌단 채색만으로는 BPMN 기본 패턴에서 교차가 k(k−1)/2로 늘기 때문 [검토자 측정, §8.1]. R8 TB 끼움은 **컨테이너 변·스트립·형제 간격에서만**, 같은 면의 두 접점 사이 조각은 후보에서 제외. CrossBand 끝은 I0부터 **선마다**(`Segment{gap, container_end}`) 표현(닻은 빈 레인 자리표시로만). 점 모양의 접점은 **막대 행**에 놓이고 측정이 그 행을 더한다. R3′는 교차축 순 한 번의 스윕으로 정의. R6↔R8 순서는 R3′ → R8 → R6 한 번(순환 없음). 포함 관계의 자식은 객체 또는 **선**(시퀀스 프레임). LR 이름표는 제 선 바로 옆 제 트랙.
- v4의 변경: (N1) 넓힐 경계가 없는 곧은 선·짧은 구간의 이름표는 **끝 라벨**로 — 출발 접점 열 + 2(`side_label_x`), 그 면의 R3 간격이 `이름표 폭 + 3`(`port_spacing_for`) — 둘째 기제 없음(v5에서 정정: 끝 라벨은 R6 구간에 넣지 않고 면 늘림으로 보장). (N2) PortBar 슬롯은 글리프 열을 포함해 중심에서 `g ± 2m`로 채우고, 나가는 막대는 **마지막 글자 줄 아래**, 표식은 간격의 머리 줄에. (N3) 관계는 엄격히 셋: 시퀀스 활성 막대 = 생명선 셀 안의 Fitted 컨테이너가 메시지(선)를 Contains, Fitted 컨테이너의 흐름축 범위 = 자식(선 포함) 위치의 볼록 껍질(R15), `Note over A,B`의 범위는 가족별 배치 입력. (N4) I4에서 모든 다이어그램을 새 R6로 통일(트랙 +2~6 %는 I4 출력 변화로 수용). (N5) 컨테이너 끝은 R3 접점 순서에는 들고 `reorder`·`straighten`에서는 뺀다. (N6) §5.1 스케치·R3′ 동률 규칙·PortBar는 R3′ 뒤 좌표로 그림. 검토자 측정 [검토자 측정]: v3 R6의 교차 수 = v0.4.0 ±2 %, 트랙 +2~6 %, 한 노드 묶음에서 P ≈ k²/2(k=480에서 ~10⁵).
- v5의 변경: 끝 라벨화를 방향과 무관한 한 규칙으로(LR 곧은 선 이름표 포함, 사용자 결정 "전체적인 규칙에 맞게"), 끝 라벨은 R6 구간에 넣지 않고 면을 늘려 덮지 않음을 보장(사용자 결정), PortBar 폭·높이 공식에 양 끝 캡 포함, 시퀀스 활성 범위 = 메시지 껍질 + `deactivate` 위치(배치 입력, 사용자 결정), 선 자식의 포함은 DAG, 문서 정합성(§12 V7, §8.3, §5.1, R15 머리 줄 항).

## 1. 원칙 (dg 전체)

1. **객체 + 선 + 세 관계**(선·포함·경계). 포함 관계의 자식은 객체 또는 선이다(시퀀스 프레임이 메시지를 품는다 — V7).
2. **모양은 별도 속성.** 배치는 크기와 접점 면(변, Spread/PortBar, 길이)만 읽는다.
3. **중첩 띠 격자.** 컨테이너 = 큰 격자 칸, 자식은 내용 축을 따라.
4. **규칙 전개, 휴리스틱 금지.** 탐색·그려서 비교·되돌림·캡·가중치·patience·추정 후 보정 없음. 격자 상수(접점 간격 2, 빈 칸 1, 이름표 양옆 1)만.
5. **우선순위** 올바름 > 성능 > 메모리 > 크기. 검토 항목: "모든 단계가 선 수 k와 제약 쌍 수 P에 선형(정렬·이분 탐색의 log 제외), P ≤ k²/2, 트랙 선택 O(k·T·log k), T ≤ k".
6. **범위 제한은 설계를 해치지 않는다.** 양보는 `PlacementPolicy` 한 경계(§9)에만.

## 2. 모델 타입 (목표, 모든 다이어그램 공통)

```
Object    { id, text: Vec<Vec<String>>, shape: Shape, kind: ObjectKind }
ObjectKind = Element | Container { extent: Extent, axis: Axis }
Extent    = Fitted | CrossBand | LayerBand
Axis      = Inherited | Declared(Direction)
ObjectRef = usize
Line      { from: ObjectRef, to: ObjectRef, label, tail_label, head_label, stroke: Stroke, tail: Marker, head: Marker }
Child     = Object(ObjectRef) | Line(usize)                         // V7: 포함 관계의 자식
Graph     { objects, lines /* = Connects 관계 */, contains: Vec<(Container, Child)>, attaches: Vec<(host: ObjectRef, boundary: ObjectRef)>,
            direction, precedence: Vec<(ObjectRef, ObjectRef)> }
```
- 시퀀스·트랙·차트 가족은 가족별 부가 자료(시간 순서 = 층, 트랙 번호, 값, `Note over A,B`의 "A..B에 걸침" 같은 **배치 입력** — `precedence`와 같은 성격이며 관계가 아니다)를 따로 두되 객체·선·세 관계는 이 타입을 쓴다(§6).
- **포함의 모양**: 객체 자식은 컨테이너 하나에만 속한다(포함은 나무). 선 자식은 여러 컨테이너에 동시에 속할 수 있다(한 메시지가 A의 활성, B의 활성, alt 프레임에 함께 듦 — 선 자식의 포함은 DAG).
- **일관성 규칙(N3)**: `Child::Line`은 시퀀스 가족에서만 쓰인다 — **레이어드 가족에서 Contains의 자식은 객체만**이다(선은 두 끝 객체의 컨테이너에서 자리가 결정된다). 관계는 어느 가족에서도 셋뿐이다.
- 현재 `ir::Graph`와의 차이 [코드]: 컨테이너 끝이 `Shape::Anchor` 노드(`ir.rs group_anchor :229`, `graph.rs` 분기 10곳: 673, 769, 910, 915, 945, 966, 1108, 1302, 3766, 3773), `LayerBand`·`Axis`·`attaches`·`Child::Line` 없음, 경계 이벤트가 선으로 내려옴(`bpmn/lower.rs add_boundary_edges :344`).

## 3. 모양 인터페이스

| 질의 | 뜻 | 현재 [코드] |
|---|---|---|
| `size(text, k_in, k_out) -> (w, h)` | 본문 + 접점 막대 행/열 포함 크기 | `shape::measure :24`(접점 수를 모름) |
| `port_face(side) -> Spread(len) \| PortBar(origin, len) \| None` | 변마다 접점 방식 | `is_point_anchored :63`, `spread :1727` |
| 선 모양 → 표식 글자 수 | 간격의 꼬리·머리 줄 | `marker_glyphs :4944` |

**PortBar(V4·N2, 사용자 결정)**: 점 모양(이벤트·●·◉)에 한 변으로 k ≥ 2개의 끝이 닿으면 그 변 쪽에 **막대 행(TB)/막대 열(LR)** 하나를 두고 끝들은 막대 위의 **슬롯**에 놓인다. 들어오는 쪽과 나가는 쪽은 각자 제 막대를 가진다(TB: 위/아래 행, LR: 왼/오른 열). k ≤ 1이면 막대가 없고 글리프 칸이 접점(현재 동작).
- **슬롯(N2)**: 글리프 열 g를 슬롯으로 세고 중심에서 바깥으로 `g ± 2m`(m = 0, 1, 2, …)를 R3 정렬 순(교차축 좌표 순)으로 채운다 — k가 홀수면 g가 쓰이고(`┼`, m = 0..(k−1)/2), 짝수면 g는 비어 연결 글자만(`┬`/`┴`) 놓이며 m = 1..k/2다. 반폭 h = k−1(홀수) 또는 k(짝수), 막대 폭 = 2h + 1.
- **TB 그리기**: 들어오는 막대 행은 **첫 글자 줄 위**: k=2 → `╶┴─┬─┴╴`(`┴` = 접점에서 위로 온 선이 끝남, `┬` = g에서 아래 글리프로 연결, 사이 `─`, 양 끝 `╶ ╴`), k=3 → `╶┴─┼─┴╴`. 나가는 막대 행은 **마지막 글자 줄 아래**(이벤트의 둘째 줄 `«message»`는 글리프 아래 행의 g+2부터 쓰이므로 그 줄을 피한다), g 열에서 글리프까지 `│`로 잇고(글자 줄들 사이를 g 열이 지나간다), 모양은 거울 `╶┬─┴─┬╴`/`╶┬─┼─┬╴`. **표식(▽·▷·●…)은 막대 접점 칸이 아니라 간격의 머리/꼬리 줄에 놓인다**(상자 면과 같은 규약 `segment_span`·`marker_glyphs`). 막대는 슬롯 `2h+1`칸에 양 끝 캡 2칸을 더해 `2h+3`칸이다. 글리프 열 g = 왼쪽 가장자리 + h + 1(왼쪽 캡이 객체 안에 들도록), 객체 폭 = `max(h + 1 + (tw + 2), 2h + 3)`(tw+2 = 글리프·공백·본문, `measure :33`; h = 들어오는·나가는 막대 반폭의 최대). 예: `받음`(tw=4), k=2(h=2) → 폭 = max(3+6, 7) = 9, g = 3. 객체 높이 = 글자 줄 수 + (들어오는 막대 1) + (나가는 막대 1).
- **LR 그리기**: 들어오는 막대 열은 글리프 왼쪽 열 — 세로 `│`에 슬롯 `┤`(왼쪽에서 온 선이 끝남), 글리프 행은 `├`(접점과 같으면 `┼`), 양 끝 `╵ ╷`. 들어오는 막대가 있으면 글리프 열 = 왼쪽 가장자리 + 1(막대 열이 객체 안에 들도록). 나가는 막대 열은 **가장 넓은 글자 줄 뒤**(열 = 왼쪽 가장자리 + `tw + 2`, 들어오는 막대가 있으면 +1): 글리프 행은 이름 끝부터 막대까지 `─`로 채우고 막대 칸은 `┤`(접점이면 `┼`), 슬롯 행은 `├`. 객체 폭 = `tw + 3`(+1, 들어오는 막대가 있으면), 객체 높이 = `max(text줄, 막대 슬롯 길이 + 2)`(양 끝 캡 `╵ ╷`), 글리프 행이 막대 중심.
- **좌표(N6)**: `size(text, k_in, k_out)`는 배치 전 크기 계산용이고, 막대와 슬롯의 최종 칸은 R3′ 스윕 뒤의 접점 좌표로 그린다(접점이 옮겨지면 막대가 그만큼 길어진다 — R3′의 면 늘림). 모양 인터페이스의 유일한 확장은 "접점 수를 받는 크기"이며 접점 규칙은 R3 하나다.

## 4. 배치 규칙 R1~R16

**R1 형제 순서.** 형제 컨테이너는 `precedence` DAG 순(앞 먼저; 제약 없는 쌍은 등록 순; 순환 제약은 버림). 컨테이너 사이 선의 방향이 `precedence`를 만든다(3.1의 일반형, LayerBand 티어 포함). Element 형제는 무게중심 정렬. → **INV1**.

**R2 포함 관계를 아는 층 배정(범위마다 전역).** 뒤돌아가는 선 뒤집기 + 최장 경로; 컨테이너 끝 선은 구성원 전체와 이은 것으로(`:905-919`); CrossBand 층 범위 = 소속 범위 전체(`effective_group_ranges :1075`); LayerBand는 "띠 k < 띠 k+1" `min_layer` 바닥값(`push_outputs_below_groups :696`과 같은 수단); CrossBand 끝 선은 층 제약 없음; 경계 객체는 호스트 층; 가상 노드는 지나는 층의 컨테이너 자식(LayerBand 안을 세로로 지남, 가로 변만 직교). → **INV2**.

**R3 단일 접점 규칙.** 한 면에 닿는 끝들(나가는 선, 들어오는 선, 그 면의 경계 객체)을 **상대 끝의 교차축 중심** 순으로 정렬, 간격 `s` = 2(끝 라벨·경계 객체 이름·끝 라벨화된 이름표가 있으면 그 글자가 **면을 따라 차지하는 길이** + 3 — TB는 `폭 + 3`(`port_spacing_for :4118`), LR은 글자 높이 1이라 2로 충분)로 칸 배정; 면 길이 < `s·(k−1)+3`(PortBar는 슬롯 규칙 §3)이면 면을 그 길이로 늘림. **끝 글자가 붙은 접점이 면의 끝 쪽이면 그 접점 뒤에 글자의 면 방향 길이 + 2만큼 면을 더 늘린다**(v5, 사용자 결정: 끝 글자가 면 밖으로 삐져나가 이웃을 덮지 않게 — `spread :1727`는 중심 기준이라 끝 여유가 1~2칸뿐). 상대 끝이 **컨테이너**이면 그 정렬 키는 컨테이너 면의 교차축 좌표다(N5: 컨테이너 끝도 접점 순서에 든다). *면 자리 규칙은 축마다 하나*: 흐름축 면(객체 변, Fitted·LayerBand 변, PortBar)은 이 펼침, CrossBand 교차축 면은 선의 트랙 줄과 면 선의 교점(R6 뒤 결정). → **INV3** 같은 면의 끝은 서로 다른 칸.
*컨테이너 끝과 정렬(N5, 컨트롤러 결정)*: CrossBand 끝 선은 `reorder`(무게중심)와 `straighten`에는 **들지 않는다** — 띠는 모든 층에 걸쳐 있어 노드를 끌어당길 이유가 없다. 결과적으로 BPMN 노드 순서는 v0.4.0과 같다(v0.4.0도 `is_pool_edge`를 `make_segments`에서 빼 두 단계에 넣지 않았다 [코드 `:1005`]).

**R3′ 간격 안 접점 열 유일성(V5·N6).** 한 간격을 쓰는 모든 접점(출발·도착; 곧은 선은 한 열 한 번)을 **교차축 좌표 오름차순으로 한 번 스윕**한다. 두 접점이 같은 열이면 **곧은 선의 접점이 머물고**, 둘 다 곧지 않으면 **선 번호가 뒤인 것이 옮긴다**; 옮기는 접점은 `앞 열 + s`(s는 **그 접점의 간격**: 2 또는 `끝 라벨 폭 + 3` — 두 글자 표식·끝 라벨이 붙어 보이지 않게)로 간다; 옮긴 열이 제 면의 끝을 넘으면 넘는 만큼 그 자리에서 면을 늘린다(같은 스윕 안에서 그 열에서만, 재방문 없음). 늘린 면은 그 뒤 접점들의 좌표를 그만큼 민다(스윕이 좌표 순이라 뒤쪽만). PortBar의 막대는 이 스윕 뒤의 좌표로 그린다. → **INV3′** 한 간격에서 두 선의 세로 조각이 같은 열에 놓이지 않는다(v0.4.0의 "같은 열 공유" hard 제약과 `resolve_port_swaps` 8회 반복이 불필요). 폭 영향은 S0b에서 측정.

**R4 선의 통로 선택.** 교차축 구간은 층 사이 간격에만. Element–Element: 출발 층 뒤 간격. CrossBand 끝: Element 끝이 출발이면 그 층 뒤, 도착이면 앞 간격. CrossBand–CrossBand: 간격 0. 없으면 띠 간격(층 0 앞·마지막 층 뒤·Element 없는 문서). 형제 셀 사이는 스트립(R14). **구현 표현(V3, 컨트롤러 결정)**: 구간(`Segment`)이 `gap`과 `container_end: Option<(block, face)>`를 가지며 `segment_span`·`channel_position`은 `lnodes[from].layer`가 아니라 `segment.gap`을 쓴다; CrossBand 끝은 노드가 아니라 끝 기술자이고 가상 노드를 만들지 않는다. 닻 노드는 빈 레인 자리표시(`@bpmn-placeholder`, 1×1)로만 남는다. → **INV4** 교차축 구간은 Element가 없는 줄에만.

**R5 컨테이너 끝.** 두 끝을 가르는 테두리 변에서 끝난다: 상대 층이 컨테이너 층 범위 밖이면 흐름축 변(`segment_span :3759`), 안이면(CrossBand) 트랙 줄 × 교차축 변 칸. 표식이 그 칸을 대신한다. → **INV5**.

**R6 트랙 배정 = 교차 최소화 선후 규칙 + 위상 순서 (V1, 사용자 결정).**
- 입력: 간격의 모든 선의 구간 `[lo_i, hi_i]` = 두 끝 열(이름표 칸 포함, R8)의 범위에 R12의 빈 칸 1을 양쪽에 더한 것. R3′ 뒤라 모든 접점 열이 서로 다르다.
- 제약 생성: 접점 열을 정렬해 두고, 구간 i마다 그 안에 **엄격히** 든 다른 선 j의 접점 열 p_j를 이분 탐색으로 모은다. p_j가 j의 **나가는**(출발) 접점이면 j의 세로 조각이 위에서 내려오므로 **j가 i보다 위**(트랙 번호 작음); **들어오는**(도착) 접점이면 **j가 i보다 아래**. CrossBand 면 끝은 세로 조각이 없어 제약을 만들지 않는다. 모든 제약은 soft다(hard 제약은 R3′로 사라짐).
- 순서: 위상 정렬. 준비된 것 가운데 `(lo, hi, 선 번호)` 최소를 뽑고, 준비된 것이 없으면(순환) 남은 것 가운데 `(lo, hi, 선 번호)` 최소를 뽑아 그것으로 들어오는 제약을 버린다 — 규칙이지 탐색이 아니다.
- 트랙: 그 순서로, 트랙 번호 ≥ (선행자들의 트랙 최대 + 1)인 **가장 낮은 빈 트랙**(그 트랙의 기존 구간과 겹치지 않는 첫 트랙; 트랙마다 구간 목록을 끝 좌표 정렬로 들고 이분 탐색).
- 비용: 정렬 O(k log k); 제약 생성 O(k log k + P), P = (구간, 안에 든 접점) 쌍 수로 **P ≤ k²/2**(한 노드에서 같은 쪽으로 가는 묶음이 최악: 모든 구간이 서로를 품는다; [검토자 측정] k=480에서 P ≈ 10⁵, 문제 없음); 위상 정렬 O(k + P); 트랙 선택은 선마다 "선행자 최대 + 1부터 가장 낮은 빈 트랙"을 찾는 데 트랙당 O(log k)(끝 좌표 정렬 목록의 이분 탐색)이고 트랙 수 T ≤ k이므로 O(k·T·log k) ≤ O(k²·log k) 상한, 실제로는 T가 최대 클릭 + 순환 수 정도다. 검토 항목(V1): "모든 단계가 k와 P에 선형(정렬·이분 탐색의 log 제외), P ≤ k²/2". 간격 크기 = `꼬리 줄 + 이름표 줄 + 트랙 수 + 머리 줄`.
- → **INV6** 같은 트랙의 두 구간은 겹치지 않고(빈 칸 1), 제약을 어기는 교차는 순환이 끊긴 자리에서만 생기며, **트랙 수는 최대 클릭을 넘을 수 있다**(교차를 줄이는 대가). 근거 [검토자 측정, `bench/le.rs` 재실행]: "노드 하나 → 같은 쪽 풀로 메시지 k개"에서 좌단 채색은 교차 k(k−1)/2(k=24: 276), v0.4.0 선후 규칙은 0; `loadL`형 간격(k=49)은 v0.4.0 46트랙/761교차 vs 좌단 31/717. **v3 R6(이 규칙)의 측정** [검토자 측정]: 교차 수 = v0.4.0 ±2 %, 트랙 수 +2~6 %(순환을 좌표로 끊는 방식의 차이). 이 규칙은 v0.4.0 `assign_channels :2063`의 선후 조건을 유지하고 비용만 O(k³) → O(k log k + P)로 내린 것이다(v0.4.0은 쌍 전수 O(k²)·`ready.remove(0)`+정렬·`minimum` 필터 O(k²) — [검토자 측정] k=480 → 17 ms, k=960 → 141~192 ms).

**R7 테두리 가로지르기.** 직교로만(`┼`). 교차축 구간은 간격 줄에서 세로 변만, 세로 조각은 접점 열에서 가로 변만. → **INV7** 테두리 칸은 `┼` 또는 면 표식으로만 바뀌고 T자 이음이 되지 않는다.

**R8 이름표 = 예약된 칸.**
- **TB**: 이름표는 제 트랙 줄 위. **자르는 열** = 컨테이너 세로 변 + 그 간격의 모든 접점 열(R3′ 뒤 확정) + 곧은 선·가상 노드 열. 구간을 자르는 열로 나눈 조각 가운데 **같은 면의 두 접점이 양쪽 경계인 조각은 후보에서 뺀다**(V2: 그 사이에는 이름표를 둘 수도, 넓힐 수도 없다 — `insert_across :2382`는 `across ≥ at`인 노드만 밀고 `at`을 품은 노드는 넓히지 않는다 [코드]). 남은 조각 가운데 가운데에 가장 가까운, `이름표 폭 + 2`가 드는 조각의 가운데. 드는 조각이 없으면 가운데에 가장 가까운 **넓힐 수 있는 경계**에서 끼운다: 넓힐 수 있는 경계 = 컨테이너 변(그 컨테이너의 안쪽 패드 앞, `widen_lane_to_place :2361`과 같은 자리), 형제 셀 사이 스트립(뒤 셀의 `start`), 같은 층 형제 노드 사이 간격(뒤 노드의 `across`, `gap_between :871`). 끼우는 칸 수 = `이름표 폭 + 2 − 조각 길이`. 끼움은 단조 이동이라 겹침 관계가 보존된다.
- **끝 라벨화(N1·v5, 사용자 결정 — 방향과 무관한 한 규칙)**: 구간 안에 넓힐 수 있는 경계가 없는 경우 — 곧은 선(출발 위치 = 도착 위치, 예: 게이트웨이의 `예` 가지), 두 끝이 같은 면의 접점 사이에만 걸친 짧은 구간 — 이름표는 **끝 라벨**로 다룬다. 끝 라벨의 자리는 그 방향의 기존 끝 라벨 규약 하나로 정해진다: 출발 접점에서 교차축으로 한 걸음 옆, 간격의 꼬리 쪽(TB: 접점 열 + 2, 꼬리 줄 — `side_label_x :4111`; LR: 접점 행 − 1, 꼬리 열들 — `tail_label`을 `exit − 1`에 쓰는 규약 `:3913`과 같음, 축을 바꾼 거울). 끝 라벨은 **R6 구간에 넣지 않는다**(트랙 줄이 아니라 꼬리에 있으므로) — 대신 (a) 그 면의 R3 간격이 글자의 면 방향 길이 + 3이 되어 이웃 접점의 선과 겹치지 않고, (b) 끝 쪽 접점이면 R3의 면 늘림으로 면 밖으로 나가지 않으며, (c) 글자의 흐름축 길이(TB 1줄, LR 이름표 폭)는 그 간격의 꼬리 크기에 더해진다(R15). v0.4.0의 끝 라벨 규칙을 이름표에도 그대로 쓰는 것이며, "선 옆 후보 자리 탐색"(`choose_label_x`의 `[right, left, right+1..3]`)이나 LR 인라인 덮어쓰기(`─예───▶`) 같은 둘째 기제는 없다. 예: `examples/bpmn.md` 3번 그림 LR의 `예`는 게이트웨이 오른쪽 접점의 한 줄 위, 간격 꼬리 열에 놓이고 선은 그 아래 줄을 곧게 지난다.
- **LR(V8, 사용자 결정)**: 이름표는 **제 선의 트랙 바로 옆**, 제 이름표 트랙에 가로로 놓인다 — 선 트랙과 이름표 트랙이 번갈아 서며(이름표 있는 선만) 간격 폭 = Σ(선 트랙) + Σ(제 이름표 폭 + 1). 이름표 줄 = 제 세로 구간의 가운데 줄. 다른 선의 가로 조각(접점 → 제 트랙)이 그 줄에서 이 이름표 열을 지나면 겹치므로, 이름표 줄은 제 구간 안에서 가운데에 가까운 순으로 "어떤 가로 조각 줄도 아닌 줄"을 택한다(가로 조각 줄은 R6 뒤 모두 알려진 유한 집합, 구간 길이 ≥ 3이면 반드시 있음; 구간 길이 < 3이면 **그 간격의 머리 크기를 1 늘린다** — 간격 전체에 걸리는 R15의 간격 크기 항이다). 선 위에 덮어 쓰는 일은 없다.
- → **INV8** 이름표는 항상 그려지고 테두리·선·글자를 덮지 않는다(`lr_labels.md` 현재 세 이름표 탈락 [측정]).

**R6↔R8 순서(V6).** 자르는 열은 접점(R3′)·곧은 선·컨테이너 변만으로 정해지고 트랙에 의존하지 않으므로 순서는 **R3′ → R8 자리(구간을 이름표 칸으로 넓힘; 필요하면 끼움 → 좌표 평행이동) → R6 한 번**이다. 순환은 없다. LR의 "가로 조각 줄 피하기"만 R6 뒤 결정이며 트랙에 영향을 주지 않는다(이름표 트랙은 선 트랙 옆에 예약된 제 열이라).

**R9 경계 관계.** 경계 객체 B는 호스트 H의 흐름축 앞면(TB 아래, LR 오른쪽; H가 컨테이너면 마지막 층 쪽 변)에서 R3 목록의 칸 하나(정렬 키 = B의 나가는 선 상대 중심 평균, 없으면 +∞, 같으면 선언 순; **R3 간격 s에 B의 이름 폭 포함** — V9). 글리프가 테두리 글자를 대신한다. B의 선은 그 칸을 접점으로 R4~R6, 들어오는 선은 H 뒤 간격에서. B의 글자: TB는 접점 열 오른쪽 두 칸부터 간격 첫 줄들(`side_label_x :4111`), LR은 글리프 오른쪽 이름표 트랙. → **INV9**.

**R10 시도 안의 결정은 한 번.** 한 시도 안에서 배치 → R3·R3′ → R8 → R6 → 폭 검사 → 그리기 각 1회, 되돌림 없음, 폭 초과면 `None`. 시도 사다리(`render :22-26`, `build :287-337`)는 G6(I4). → **INV10** 시도당 배치 1회.

**R11 그리기** 캔버스 1회. **R12 상수** 접점 간격 2, 빈 칸 1(R6 구간 양쪽 패딩과 같은 값), 이름표 양옆 1, 층 사이 최소 3.

│           │ │            ○╌┼╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╮              │  ← 띠 간격(층 0 앞) 트랙 0: 파트너 → 받음 (위); 판매사 왼쪽 변은 ┼

│           │ │            │ │          ▽    ▽              │  ← 머리 줄: 표식은 여기(막대 칸이 아님)
