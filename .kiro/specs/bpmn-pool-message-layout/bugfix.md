# 버그 수정 - bpmn-pool-message-layout

## 정의
BPMN 협업 다이어그램에서 풀 사이 메시지 흐름이 읽는 방향(왼쪽에서 오른쪽, 위에서 아래)으로 흐르고 서로 겹치지 않게 하기 위해, 풀 순서와 메시지 통로, 노드 쪽 접점을 바로잡는 결함 수정이다.

## 재현 절차
1. 환경: dg 0.4.0 (`v0.4.0`, `513e867`), `cargo build --release`, `./target/release/dg -P -s none -w 120 --direction <lr|tb> <파일>`.
2. 입력 A(단방향, 받는 풀을 먼저 선언): 풀 `shop`(시작 이벤트 `r`, 태스크 `t`) 다음에 블랙박스 풀 `customer`, 흐름 `customer --> r`, `r --> t`. 관찰: 가로 배치에서 고객 풀이 아래에 놓여 메시지가 `╰╌╌╌╌╌╮` 위로 올라가 `△`에 닿는다. 세로 배치에서 고객 풀이 오른쪽에 놓여 메시지가 `○ 주문 접수◁┼╌╌╮`처럼 오른쪽에서 왼쪽으로 온다.
3. 입력 B(마주 보는 풀과 사이 풀): 블랙박스 풀 `c`, `v`, `w`와 풀 `p1`(태스크 가, 나, 다), 흐름 `c --> v`, `c --> w`, `v --> c`, `v --> a`, `b --> c`(그리고 `a --> b`, `b --> d`). 관찰: 가로 배치에서 고객과 공급자 사이 한 줄 통로에서 선이 `╰╌┼╌┤ ╎`처럼 합쳐진다. 세로 배치에서 공급자 풀을 지나는 `c --> w`가 `v --> c`와 `○┴╌╌▷╌╌…`로 같은 칸을 쓴다.
4. 입력 B2(마주 보는 풀, 메시지 방향이 순방향): 풀 `p1`(태스크 가), 블랙박스 풀 `c`, `v`, 풀 `p2`(태스크 나, 다), 흐름 `y --> x`, `c --> x`, `a --> v`, `v --> y`. 관찰: 가로 배치에서 고객과 공급자 사이 통로에서 `a --> v`와 `v --> y`가 `╭╌┤`로 합쳐진다(3.1 적용 후 풀 순서에서는 `├┴╌╌╌╌╌╌╌╌╮`).
5. 입력 C(한 노드에 메시지 여럿): 블랙박스 풀 `c`, `v`와 풀 `p1`(태스크 가, 나), 흐름 `a --> b`, `c --> v`, `v --> c`, `a --> c`, `b --> v`, `c --> b`. 관찰: 세로 배치에서 `│ 나 │◁┼╌╌┴┼`로 `b --> v`의 `○`가 사라지고 선이 `┴`로 합쳐진다.
6. 입력 D(한 노드에 메시지 셋): 블랙박스 풀 `c`, 풀 `p1`(태스크 가), 흐름 `a --> c`, `c --> a`, `a --> c`. 관찰: 가로 배치에서 `가` 아래에 `○` 하나만 있고 `c --> a`의 빈 삼각형이 노드 쪽에 없으며, 통로가 `╭╌╌╌┤`로 합쳐진다. 세로 배치에서도 `○┼╌╌┼○`로 노드 쪽 끝이 한 칸이다.
7. 입력 E(메시지 길에 다른 노드): 풀 `shop`(시작 이벤트 `received`, 사용자 태스크 `review`, 텍스트 주석 `note`, 흐름 없는 텍스트 주석 `note2` "기록") 다음에 블랙박스 풀 `customer`, 흐름 `customer --> received`, `received --> review`, `note --> review`, `review --> customer`. 관찰: 가로 배치에서 `customer --> received`가 `기록` 상자를 세로로 지나 테두리가 `├╌╌╌╌╌╌┐`, `├╌╌╌╌╌╌┘`로 바뀐다. 세로 배치에서 같은 선이 `◁╌╌┬╌╌╌╌╌╌┬╌┼`로 `기록` 윗변을 지난다. 3.1을 적용한 `examples/bpmn.md` 두 번째 그림에서도 같은 선이 주석 `30분 안에 검토`의 왼쪽 테두리를 지난다.
8. 입력 F(이름 있는 메시지가 풀 테두리를 가로지름): 풀 `고객`(태스크 `보내기`)과 풀 `판매사`(메시지 시작 이벤트 `받음`, 태스크 `처리`), 메시지 흐름 `주문`(`보내기` → `받음`), 시퀀스 흐름 `받음` → `처리`. 관찰: 세로 배치에서 `╰╌╌╌╌╌┼주문╌╌╌╌╌╮`로 이름표 `주문`이 판매사 풀 왼쪽 테두리 칸을 덮어 그 행의 테두리 `│`가 사라진다. 3.1을 적용한 `examples/bpmn.md` 세 번째 그림 세로 배치에서도 `│╭╌╌주문╌╌╌▷○`로 같다.
9. 입력 H(점 모양 이벤트 둘에 메시지 둘씩): 블랙박스 풀 `고객`, `파트너`와 풀 `판매사`(메시지 시작 이벤트 `받음`, 태스크 `처리`, 끝 이벤트 `끝`), 메시지 `주문`(고객 → 받음), `문의`(파트너 → 받음), `답신`(끝 → 고객), `보고`(끝 → 파트너), 시퀀스 흐름 `받음 → 처리 → 끝`. 관찰: 세로 배치에서 `받음` 쪽에 빈 삼각형이 `◁` 하나뿐이고 `주문` 이름표가 없으며, `끝` 쪽은 `◉ 끝○╌╌╌답신┼╌╌┴보고`로 `○` 하나에 두 선이 `┴`로 합쳐진다.
10. 입력 I(이름 있는 메시지 셋이 세 풀을 돎): 블랙박스 풀 `고객`, `물류`와 풀 `판매사`(태스크 `처리`), 메시지 `주문서`(고객 → 처리), `배송요청`(처리 → 물류), `배송완료통지`(물류 → 고객). 관찰: 가로 배치에서 이름표 세 개가 모두 그려지지 않는다. 세로 배치에서 `주문서`와 `배송완료통지`가 그려지지 않는다.

## 범위
- **포함**: 풀(블랙박스와 일반 풀 모두) 사이 메시지 방향에 따른 풀 순서, 마주 보는 두 풀이 같은 사이 통로를 쓸 때의 줄 배정, 다른 풀을 가로지르는 메시지의 겹침, 한 노드에 메시지가 여럿 붙을 때 노드 쪽 접점, 메시지 선이 끝 노드로 가는 길에 있는 같은 풀의 다른 노드(텍스트 주석 포함), 메시지 이름표가 놓이는 자리. BPMN 다이어그램에서 메시지와 같은 간격을 쓰는 시퀀스 흐름의 줄 배정, BPMN 배치의 순서·곧게 펴기·폭 결정 단계(2026-10-08 사용자 결정: 규칙 하나로 통일).
- **제외**: 풀 안 레인 순서, BPMN이 아닌 다이어그램의 배치, 이벤트 글자 정렬(`bpmn-event-glyph-alignment`), 건너뛰기 글자 `◠` 커버리지, 흐름 표기(선 무늬, 표식 모양).

## 동작

### 1. 현재 동작 (결함)
- 1.1: [두 풀 사이 메시지가 한 방향뿐이고 받는 풀을 먼저 선언] 받는 풀이 앞(가로 배치 위, 세로 배치 왼쪽)에 놓여 메시지가 아래에서 위로, 오른쪽에서 왼쪽으로 흐른다.
- 1.2: [마주 보는 두 풀이 양방향 메시지로 같은 사이 통로를 씀] 두 방향의 선이 같은 통로 줄에서 이음 글자(`┼` `┤`)로 합쳐진다.
- 1.3: [메시지가 끝이 아닌 풀을 가로지름] 가로지르는 선이 다른 메시지 선과 같은 칸을 써서 `┴`처럼 합쳐진다.
- 1.4: [한 노드에 메시지가 둘 이상 붙음] 노드 쪽 끝이 한 칸에 모여 어떤 메시지의 `○`나 빈 삼각형이 덮여 보이지 않고 선이 합쳐진다.
- 1.5: [메시지가 끝 노드로 가는 길에 같은 풀의 다른 노드가 있음] 메시지 선이 그 노드 상자를 지나 테두리가 이음 글자(`├` `┬`)로 바뀐다.
- 1.6: [이름 있는 메시지가 풀이나 레인 테두리를 가로지르는 구간에 이름표가 놓임] 이름표 글자가 테두리 칸을 덮어 그 행(열)의 테두리가 끊긴다.
- 1.7: [이름 있는 메시지가 여럿이고 이름표 놓을 자리가 좁음] 이름표 일부나 전부가 그려지지 않는다(입력 H, I).

### 2. 기대 동작
- 2.1: [두 풀 사이 메시지가 한 방향뿐] 보내는 풀이 받는 풀보다 앞(가로 배치 위, 세로 배치 왼쪽)에 놓여 메시지가 위에서 아래, 왼쪽에서 오른쪽으로 흐른다. 메시지 방향이 선언 순서보다 우선한다(사용자 결정). 방향 조건이 없거나 서로 맞서는 풀(양방향, 순환)은 0.4.0의 배치 순서(풀의 노드가 처음 나온 순서, 노드 없는 풀은 메시지에서 처음 언급된 순서)를 따른다.
- 2.2: [1.2와 같은 풀] 같은 간격을 쓰는 선(시퀀스·메시지)은 서로 같은 칸을 같은 방향으로 쓰지 않고 이음 글자로 합쳐지지 않으며, 선끼리의 교차는 서로 맞물려 피할 수 없는 경우에만 생긴다. 줄 순서는 모든 선에 같은 하나의 규칙으로 정한다(2026-10-08 사용자 결정으로 앞선 줄 순서 결정 — 출발점 왼쪽부터, 붙은 풀 면 쪽 줄 — 을 대체; 규칙은 설계서).
- 2.3: [1.3과 같은 메시지] 끝이 아닌 풀을 가로질러도 되지만 다른 메시지 선과 같은 칸을 같은 방향으로 쓰지 않고, 직교 교차는 기존 건너뛰기 규칙을 따른다.
- 2.4: [1.4와 같은 노드] 모든 객체(노드, 이벤트, 풀)의 끝은 하나의 접점 규칙으로 서로 다른 칸에 놓이고(점 모양 이벤트는 접점 막대 `╶┴─┬─┴╴`), 모든 메시지의 `○`와 빈 삼각형이 보이며 선이 합쳐지지 않는다.
- 2.5: [1.5와 같은 메시지] 메시지 선의 가로(교차축) 구간은 노드가 없는 층 사이 간격 줄에만 놓여, 끝 노드 말고 다른 노드 상자나 흐름 화살촉 칸을 지나지 않고 노드 테두리 글자와 화살촉이 그대로다. 서브프로세스·그룹 상자와 풀 테두리는 직교로 가로지를 수 있다(사용자 결정).
- 2.6: [1.6과 같은 메시지] 이름표가 풀, 레인 테두리와 다른 선, 노드를 덮지 않고 이름표 글자가 모두 보이며, 테두리는 끊기지 않는다(사용자 결정: 이번 수정에 포함).
- 2.7: [1.7과 같은 문서] 모든 메시지 이름표가 그려지고 아무것도 덮지 않는다.

### 3. 불변 동작 (회귀 방지)
- 3.1: [풀 사이 메시지가 없거나 모든 메시지가 이미 순방향인 문서] 풀 순서가 0.4.0과 같다. 그 밖의 렌더링(노드 순서·자리, 메시지 통로, 접점, 이름표, 폭 결정)은 BPMN 규칙에 따라 바뀔 수 있다(2026-10-08 사용자 결정).
- 3.2: (폐기, 2026-10-08 사용자 결정) 풀 면 가운데 접점과 면 바로 바깥 통로를 유지하던 조건이다. 메시지는 노드 포트에서 간격 줄로 나가 풀 테두리와 만나는 칸에서 끝난다(L자). 소유 스펙 `bpmn-pool-lane-rendering-polish` 2.3도 함께 개정한다.
- 3.3: [풀 안 레인] 레인 순서와 중첩은 선언 순서 그대로다.
- 3.4: [BPMN이 아닌 다이어그램] 렌더링 결과가 0.4.0과 바이트 단위로 같다.
- 3.5: [흐름 표기] 메시지의 대시선, `○` 꼬리, 빈 삼각형 머리와 다른 흐름 표기가 `bpmn-flow-kind-notation` 그대로다.
- 3.6: [항상] 사용자 요구(정확성 > 성능 > 메모리 > 크기, 느리면 못 쓴다)에 따른 목표. 이 항목이 성능 목표의 유일한 정의다.
  - 측정: T = 프로세스 CPU 시간(사용자 + 시스템, 5회 중앙값, wall 시간과 uutils `timeout` 미사용). M = 최대 RSS. C = 출력 캔버스 칸 수(가로 × 세로). 비교 바이너리는 v0.4.0, cf50ba2, 수정본.
  - `T_배치(v0.4.0)`, `T_그리기(v0.4.0)`: v0.4.0에 시간 계측만 넣은 빌드(출력 바이트 동일)로 다이어그램 배치와 캔버스 그리기에 쓴 스레드 CPU 시간을 잰다. `T_그 외(v0.4.0)` = `T(v0.4.0) − T_배치 − T_그리기`(읽기·파싱·출력). `c_그리기` = `T_그리기 / C`를 `examples/*.md`와 부하 문서에서 최소제곱으로 맞춘 값.
  - 목표: BPMN 문서마다 `T ≤ 1.2·T_배치(v0.4.0) + c_그리기·C + T_그 외(v0.4.0)`이고 `T ≤ T(cf50ba2)`. `T(v0.4.0)` 대비 `examples/*.md` ≤ 1.05배, 원문으로 떨어지는 문서 ≤ 1.10배. 같은 바이너리에서 2배 입력에 ≤ 2.2배 시간. 스파이크(tasks 3.9)의 단계별 판정 기준은 이 목표에서 유도한 값이다. `M ≤ M(v0.4.0) + 1.1·24B·(C − C(v0.4.0))`.
  - 구조: 배치 복제 0. BPMN 경로에 steering R12 목록 밖 상수와 반복 횟수 상한이 없다(비 BPMN의 legacy는 steering 호환 경계 표). 모든 단계가 k, P, C에 선형(log 제외).
  - 크기: `graph.rs` 증가 ≤ v0.4.0 + 500줄, 릴리스 바이너리 증가 ≤ 3%.
