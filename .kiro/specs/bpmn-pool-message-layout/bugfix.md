# 버그 수정 - bpmn-pool-message-layout

## 정의
BPMN 협업 다이어그램에서 풀 사이 메시지 흐름이 읽는 방향(왼쪽에서 오른쪽, 위에서 아래)으로 흐르고 서로 겹치지 않게 하기 위해, 풀 순서와 메시지 통로, 노드 쪽 접점을 바로잡는 결함 수정이다.

## 재현 절차
1. 환경: dg 0.4.0 (`v0.4.0`, `513e867`), `cargo build --release`, `./target/release/dg -P -s none -w 120 --direction <lr|tb> <파일>`.
2. 입력 A(단방향, 받는 풀을 먼저 선언): 풀 `shop`(시작 이벤트 `r`, 태스크 `t`) 다음에 블랙박스 풀 `customer`, 흐름 `customer --> r`, `r --> t`. 관찰: 가로 배치에서 고객 풀이 아래에 놓여 메시지가 `╰╌╌╌╌╌╮` 위로 올라가 `△`에 닿는다. 세로 배치에서 고객 풀이 오른쪽에 놓여 메시지가 `○ 주문 접수◁┼╌╌╮`처럼 오른쪽에서 왼쪽으로 온다.
3. 입력 B(마주 보는 풀과 사이 풀): 블랙박스 풀 `c`, `v`, `w`와 풀 `p1`(태스크 가, 나, 다), 흐름 `c --> v`, `c --> w`, `v --> c`, `v --> a`, `b --> c`(그리고 `a --> b`, `b --> d`). 관찰: 가로 배치에서 고객과 공급자 사이 한 줄 통로에서 선이 `╰╌┼╌┤ ╎`처럼 합쳐진다. 세로 배치에서 공급자 풀을 지나는 `c --> w`가 `v --> c`와 `○┴╌╌▷╌╌…`로 같은 칸을 쓴다.
4. 입력 C(한 노드에 메시지 여럿): 블랙박스 풀 `c`, `v`와 풀 `p1`(태스크 가, 나), 흐름 `a --> b`, `c --> v`, `v --> c`, `a --> c`, `b --> v`, `c --> b`. 관찰: 세로 배치에서 `│ 나 │◁┼╌╌┴┼`로 `b --> v`의 `○`가 사라지고 선이 `┴`로 합쳐진다.
5. 입력 D(한 노드에 메시지 셋): 블랙박스 풀 `c`, 풀 `p1`(태스크 가), 흐름 `a --> c`, `c --> a`, `a --> c`. 관찰: 가로 배치에서 `가` 아래에 `○` 하나만 있고 `c --> a`의 빈 삼각형이 노드 쪽에 없으며, 통로가 `╭╌╌╌┤`로 합쳐진다. 세로 배치에서도 `○┼╌╌┼○`로 노드 쪽 끝이 한 칸이다.
6. 입력 E(메시지 길에 다른 노드): 풀 `shop`(시작 이벤트 `received`, 사용자 태스크 `review`, 텍스트 주석 `note`, 흐름 없는 텍스트 주석 `note2` "기록") 다음에 블랙박스 풀 `customer`, 흐름 `customer --> received`, `received --> review`, `note --> review`, `review --> customer`. 관찰: 가로 배치에서 `customer --> received`가 `기록` 상자를 세로로 지나 테두리가 `├╌╌╌╌╌╌┐`, `├╌╌╌╌╌╌┘`로 바뀐다. 세로 배치에서 같은 선이 `◁╌╌┬╌╌╌╌╌╌┬╌┼`로 `기록` 윗변을 지난다. 3.1을 적용한 `examples/bpmn.md` 두 번째 그림에서도 같은 선이 주석 `30분 안에 검토`의 왼쪽 테두리를 지난다.
7. 입력 F(이름 있는 메시지가 풀 테두리를 가로지름): 풀 `고객`(태스크 `보내기`)과 풀 `판매사`(메시지 시작 이벤트 `받음`, 태스크 `처리`), 메시지 흐름 `주문`(`보내기` → `받음`), 시퀀스 흐름 `받음` → `처리`. 관찰: 세로 배치에서 `╰╌╌╌╌╌┼주문╌╌╌╌╌╮`로 이름표 `주문`이 판매사 풀 왼쪽 테두리 칸을 덮어 그 행의 테두리 `│`가 사라진다. 3.1을 적용한 `examples/bpmn.md` 세 번째 그림 세로 배치에서도 `│╭╌╌주문╌╌╌▷○`로 같다.

## 범위
- **포함**: 풀(블랙박스와 일반 풀 모두) 사이 메시지 방향에 따른 풀 순서, 마주 보는 두 풀이 같은 사이 통로를 쓸 때의 줄 배정, 다른 풀을 가로지르는 메시지의 겹침, 한 노드에 메시지가 여럿 붙을 때 노드 쪽 접점, 메시지 선이 끝 노드로 가는 길에 있는 같은 풀의 다른 노드(텍스트 주석 포함), 메시지 이름표가 놓이는 자리.
- **제외**: 풀 안 레인 순서, 메시지가 아닌 흐름의 배치, 이벤트 글자 정렬(`bpmn-event-glyph-alignment`), 건너뛰기 글자 `◠` 커버리지, 흐름 표기(선 무늬, 표식 모양).

## 동작

### 1. 현재 동작 (결함)
- 1.1: [두 풀 사이 메시지가 한 방향뿐이고 받는 풀을 먼저 선언] 받는 풀이 앞(가로 배치 위, 세로 배치 왼쪽)에 놓여 메시지가 아래에서 위로, 오른쪽에서 왼쪽으로 흐른다.
- 1.2: [마주 보는 두 풀이 양방향 메시지로 같은 사이 통로를 씀] 두 방향의 선이 같은 통로 줄에서 이음 글자(`┼` `┤`)로 합쳐진다.
- 1.3: [메시지가 끝이 아닌 풀을 가로지름] 가로지르는 선이 다른 메시지 선과 같은 칸을 써서 `┴`처럼 합쳐진다.
- 1.4: [한 노드에 메시지가 둘 이상 붙음] 노드 쪽 끝이 한 칸에 모여 어떤 메시지의 `○`나 빈 삼각형이 덮여 보이지 않고 선이 합쳐진다.
- 1.5: [메시지가 끝 노드로 가는 길에 같은 풀의 다른 노드가 있음] 메시지 선이 그 노드 상자를 지나 테두리가 이음 글자(`├` `┬`)로 바뀐다.
- 1.6: [이름 있는 메시지가 풀이나 레인 테두리를 가로지르는 구간에 이름표가 놓임] 이름표 글자가 테두리 칸을 덮어 그 행(열)의 테두리가 끊긴다.

### 2. 기대 동작
- 2.1: [두 풀 사이 메시지가 한 방향뿐] 보내는 풀이 받는 풀보다 앞(가로 배치 위, 세로 배치 왼쪽)에 놓여 메시지가 위에서 아래, 왼쪽에서 오른쪽으로 흐른다. 메시지 방향이 선언 순서보다 우선한다(사용자 결정). 방향 조건이 없거나 서로 맞서는 풀(양방향, 순환)은 0.4.0의 배치 순서(풀의 노드가 처음 나온 순서, 노드 없는 풀은 메시지에서 처음 언급된 순서)를 따른다.
- 2.2: [1.2와 같은 풀] 메시지를 출발점이 왼쪽(세로 배치는 위)인 것부터, 같으면 오른쪽(흐름 방향)으로 가는 것부터 배치하고(사용자 결정), 먼저 배치한 메시지가 자기를 보내는 풀 면 쪽 통로 줄을 쓴다(사용자 결정). 두 방향의 선은 같은 칸을 같은 방향으로 쓰지 않는다.
- 2.3: [1.3과 같은 메시지] 끝이 아닌 풀을 가로질러도 되지만 다른 메시지 선과 같은 칸을 같은 방향으로 쓰지 않고, 직교 교차는 기존 건너뛰기 규칙을 따른다.
- 2.4: [1.4와 같은 노드] 메시지마다 노드 쪽 끝 칸이 따로 있어 모든 메시지의 `○`와 빈 삼각형이 노드 쪽에 보이고 선이 합쳐지지 않는다.
- 2.5: [1.5와 같은 메시지] 메시지 선이 끝 노드 말고 다른 노드 상자를 지나지 않고, 노드 테두리 글자가 그대로다(사용자 결정: 이번 수정에 포함).
- 2.6: [1.6과 같은 메시지] 이름표가 풀, 레인 테두리와 다른 선, 노드를 덮지 않고 이름표 글자가 모두 보이며, 테두리는 끊기지 않는다(사용자 결정: 이번 수정에 포함).

### 3. 불변 동작 (회귀 방지)
- 3.1: [풀 사이 메시지가 없거나 모든 메시지가 이미 순방향인 문서] 풀 순서와 렌더링 결과가 0.4.0과 같다.
- 3.2: [블랙박스 풀 면과 노드마다 메시지가 하나씩인 문서] 풀 면 가운데 접점과 면 바로 바깥 통로가 0.4.0과 같다(풀 순서만 2.1에 따라 바뀔 수 있다).
- 3.3: [풀 안 레인] 레인 순서와 중첩은 선언 순서 그대로다.
- 3.4: [BPMN이 아닌 다이어그램] 렌더링 결과가 0.4.0과 바이트 단위로 같다.
- 3.5: [흐름 표기] 메시지의 대시선, `○` 꼬리, 빈 삼각형 머리와 다른 흐름 표기가 `bpmn-flow-kind-notation` 그대로다.
- 3.6: [항상] `examples/*.md` 렌더링의 실행 시간과 최대 메모리(RSS)가 0.4.0 대비 10% 이내로 늘고, 메시지가 많은 문서(블랙박스 풀 여럿, 메시지 수십 개)에서 메시지 수를 두 배로 늘려도 실행 시간이 4배 미만이다(사용자 요구: 최종 성능, 메모리 점검 필수).
